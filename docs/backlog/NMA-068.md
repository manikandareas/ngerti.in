## Objective

Use the existing backend to make the native shell and conversation behave like the current desktop, including persistence, lost acknowledgement and reconnect. Fixtures remain verification tools rather than a replacement for live projections.

## Implementation units

1. Compose the native shell/sidebar/search, selection, header/model picker, contextual panel opening, sidebar skeletons and compact-window behavior from the baseline. Keep Settings and contextual pages within the workspace.
2. Implement version-checked Rust DTOs, HTTP requests, atomic snapshot/history and owner-wide event decoding/filtering. Preserve ordered cursors, entity revisions, deletion, timeouts, bounded queues and visibility reconciliation; cancel stale scope reads.
3. Introduce per-profile native storage for plain drafts, selected workspace/preferences and durable pending commands/submissions. Persist the exact operation identity/path/body and attachment bytes before dispatch. A projection cursor is persisted only with its consistent projection checkpoint; otherwise recover from a fresh snapshot.
4. Connect the composer to upload/admission and authoritative message parts/artifact IDs. Support DM/group recipient semantics, queued inputs/edit/delete, contextual steering, native questions/approvals, failed opener continuation, exact-input retry and requested-versus-confirmed stop.
5. Port chronology, publication ordering, group attribution, friendly transient activity, bounded streaming presentation and follow-bottom/history-reading behavior. Reuse server state; opening an existing chat must not create inference.
6. Implement Create agent and Create group using backend defaults and durable opener receipts. Retain one intentional operation through double submit/lost acknowledgement/restart, including missing provider/default and unknown native outcome states.

## Acceptance criteria

- [ ] The actual API populates Tobi/agents/groups/history and correct sidebar/header identities; light/dark, loading/empty/error and compact-window layouts match the manifest. No separate global Agents/Goals/Workspace navigation is introduced.
- [ ] Event reconnect/overlap/revision/delete and incomplete UTF-8/SSE frame cases do not duplicate or drop public content. Snapshot failure recovers without wiping authored input; returning to foreground reconciles a missed answer without another submission.
- [ ] Plain per-thread drafts survive full Quit/relaunch. Staged files and unresolved operations follow their reference lifecycle; no orphan file chips are restored. Replaying a lost acknowledgement reuses the exact persisted operation/body and produces one admission/creation/edit.
- [ ] Queue order, edit/delete receipts, steering applicability and questions/approvals are verified through authoritative state. Submitted, queued, running, waiting, cancel requested, confirmed stopped and unknown remain distinct.
- [ ] Create-agent/group, failed initial opening and safe retry preserve one identity/conversation/opener. Existing-conversation open/reopen generates no inference. Selected billing/model/recipient never changes silently.
- [ ] Day boundaries/clocks retain the reference device time-zone and publication semantics. Group messages/cards identify their author; DM rows and Goal/Routine bars follow their existing presentation. Administrative/private handoff content stays hidden.
- [ ] First visible frame and Send reveal the latest content when appropriate; history reading stays anchored through streamed bursts, composer resizing, earlier-page loads and panel changes. Final/history/reduced-motion text flushes without delayed leftovers or broken Unicode.
- [ ] Native/API evidence covers actual snapshot/events/receipts and controlled lost-ack/reconnect/restart cases using disposable data. Provider discovery, real inference and useful product tools are reported separately; no fixture or HTTP success is promoted to native/provider proof.
- [ ] Workspace, sidebar/header/model picker, composer, transcript and native question/approval controls are GPUI elements. The existing web-client serves only as the comparison reference and is not loaded inside the new shell.
