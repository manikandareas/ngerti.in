The three ordered units are implemented locally for the selected scoped Linux Docker environment. Hermes remains the only admission, session, scheduling, cancellation and recovery authority. The original account remains on schema 14; no original account, external resource, deployment or active engine was migrated. Work is local and uncommitted.

## Delivered behavior

The native supervisor now separates persistent owner/agent/thread workspace identity from execution generations. Independent agents and threads have separate volumes. Named projects, relative folder bindings and worktree mappings are retained in the private workspace. Native terminal, file tools, process management and the session code kernel/RPC retain their upstream schemas and results. No host directory, Docker socket or credential directory is mounted into a worker.

Background process handles, originating admissions and completion/lost receipts are durable. The existing Hermes gateway observes receipts and publishes scoped events; this observer does not admit or schedule competing model work. Gateway restart can retain a running capsule. Container retirement ends its RAM and marks unfinished jobs lost. Files and immutable action receipts survive separately. Explicit new admissions can follow a stopped incarnation; old operations are never replayed. Unknown effects remain quarantined. Queued dispatch rechecks live capability, context and authority generations after obtaining its workspace lock.

Schema 16 adds immutable file metadata, explicit binary-file sharing, message attachment references and native-job event receipts. Binary bytes live under the partition's content-addressed `files/objects` directory, outside old UTF-8 rows. Uploads use 512 KiB immutable parts, a declared SHA-256 and a 32 MiB limit. Finalization fsyncs bytes before publishing ready metadata. Retried parts reconcile against retained objects; finalized staging is removed. Unreferenced objects are inventoried for reconciliation and retained. A new upload cannot reuse an old UTF-8 artifact identity.

DM/group ingress authorizes attachment references atomically with message creation and preserves the existing request-key deduplication. Native `workspace import_file` places verified bytes in the private worker; native `read_file` performs extraction. `workspace publish_file` exports bounded regular files, commits their producing run/agent/thread and durable bytes, then publishes the artifact event. Old text artifacts remain readable. Group downloads supply their thread scope, so revoked sharing prevents later downloads. The composer uploads real files, messages retain attachment references, and results support authenticated downloads and text previews.

The `coding` native adapter selects projects, discovers scanned project instructions, provides real LSP diagnostics, takes native shadow-Git checkpoints, inspects diffs, restores selected files or safe workspace changes, and creates/releases/cleans isolated Git worktrees. Restore compares the inspected file hashes and preserves unrelated user edits. Cleanup refuses active, dirty or unmerged task work. Restoration changes files, not external effect receipts or repository history. Web controls expose these operations with an explicit agent selection.

Assigned skills may declare a bounded `native_assets` manifest of individual operator-owned files, hashes and executable flags. Only these explicit bytes are staged, without a host mount. The persona receives their native paths. Asset changes change the capability snapshot; content-only historical skills retain their identity. The verified helper executes as UID 10001, reaches the capsule's Chromium CDP endpoint and observes no provider key. Advanced skill catalog/install behavior remains NMA-034.
