# Ngertiin product scope

This repository is the authority for Ngertiin product decisions, implementation scope, acceptance and delivery status. Start with [the documentation index](docs/README.md), [feature decisions](docs/product/feature-decisions.md), and [the local backlog](docs/backlog/README.md). Explicit user decisions take precedence and must be recorded locally when they change scope.

Ngertiin is a persistent agent workspace. The November 12 direction promotes one owner-operated server with PostgreSQL, authenticated users, multiple organizations, Owner/Admin/Member roles, Workgroups, and private or organization-owned agents. Implementation is planned in [the server-organizations plan](docs/architecture/server-organizations-plan-2026-11-12.md) and NMA-072–083; the installed baseline still serves one human owner. Agents can use tools, collaborate, retain scoped memory, and continue durable responsibilities through Goals and Routine while the backend and harness host remain alive. Closing a client does not stop server work; a sleeping or powered-off server cannot execute.

## Server organizations direction — 2026-11-12

The [main plan](docs/architecture/server-organizations-plan-2026-11-12.md) owns the new model and diagrams. User roles and Workgroups are organization-local. Team agents publish shared configuration and authorized skills/knowledge while each person's conversation, memory, artifacts, native sessions and personal connections remain private. Organization and personal provider connections are explicit choices, with no silent billing fallback. Application Admin permission does not grant private transcript access.

Web-client and Tauri are the implementation targets; desktop-rs/GPUI work is paused. The central server owns harness execution and scheduling. Remote Tauri clients do not supervise that server. HTTPS with user/device sessions is the transport baseline; VPN/Tailscale is optional operator infrastructure. Enforced per-user/organization execution domains replace the singleton machine as the planned cross-human privacy boundary. These are new acceptance commitments, not claims about the current implementation.

## Product behavior

The following behavior describes the implemented single-owner foundation. NMA-072–083 adapt its identity/access boundaries according to the main plan while preserving durable creation, conversation controls and responsibility semantics.

- A default generalist agent, its primary DM and an authored welcome are created idempotently. New default and quick-created agents use random library-generated names from a single-syllable subset; existing names remain unchanged. Reopening a conversation reads history without model inference.
- One conversation workspace is the main interface. The left sidebar lists agents/groups and their chats. Detail contains contextual profile/member, Goals and Routine views; Library contains scoped saved artifacts and contextual memory/skills; Computer shows the shared machine. In the web client and Tauri host, the contextual header has Agent info and Working files icon tabs at the left and Close at the right. Agent info is the default and retains the current contextual views; Working files shows the shared file tree with bounded folder preparation and automatic background synchronization. Files use the Focus viewer, including a read-only source-code view. A persistent icon rail switches between conversation, Marketplace and Settings. The inner sidebar follows the selected screen: agents/groups, Marketplace or Settings sections. These screens share a borderless content surface, retaining the current conversation and draft when switching. See [interface behavior](docs/product/interface.md).
- Create agent immediately creates an owner-unique library-generated name, default avatar and DM using the selected connection/model/billing defaults. Create group asks for a name and valid owned agents. Each intentional creation has one durable human-authored automatic opener and admission; retry, reconnect or restart does not repeat it.
- Personalization follows useful work. Ask one necessary question, accept a clear task immediately, and update profiles or shared group directions through scoped tools. Name, role, persona, Goals and working style are examples, not a required checklist. Failed opening preserves the created entity and conversation.
- Agent identity persists across DM/group use. Native sessions, transcript, private memory and saved-artifact metadata retain their logical scope. Group updates do not rewrite every member's private profile.
- Groups contain one human owner and their agents. Valid explicit mentions select the target; semantic routing otherwise chooses the first member asked to act. Only the selected member speaks. Handoff/review transfers real work without requiring the human to relay instructions. See [conversation behavior](docs/product/conversations.md).
- Busy conversations retain FIFO input with edit/delete before dispatch. Contextual steer uses native capability; cancellation through agent-selected tools and the direct control endpoint has separate receipt semantics. Stop intent differs from native confirmation; stop run differs from stopping a Goal or Routine.
- Goals preserve outcomes needing durable ownership, progress and follow-through, or explicit Goal tracking. An ordinary request, many steps, file output, research or temporary wait alone does not require a Goal. Standalone reminders/checks may use Routine without a Goal. See [responsibilities](docs/product/goals-routine.md).

## Runtime and machine

Ngertiin owns one application lifecycle: identity, admission, queue, persistence, events, scheduling, stop intent and recovery. Codex/ChatGPT App Server and Muse Code SDK/MSP own their inner model/tool loops. Bun + TypeScript + Elysia + PostgreSQL is the NMA-072 persistence implementation. The controlled SQLite import retains the legacy owner; NMA-073 adds verified account/bootstrap binding and revocable device sessions; NMA-074 adds [organization administration, Workgroups and membership/provisioning fences](docs/architecture/organization-access.md); NMA-075 implements [private application-data scope](docs/architecture/scoped-agent-data.md), guarded legacy binding, personal/Team agents and idempotent private default-agent/DM provisioning. NMA-076 adds private execution domains. NMA-077 implements [private provider selection and server credential lifecycle](docs/architecture/provider-connections.md), with verified native two-account isolation including a Free account; NMA-078 implements [scoped app/MCP accounts and published Team skills](docs/architecture/scoped-apps-skills.md). NMA-079 verifies scoped native admission and the [2.0.0 consumer contract](docs/architecture/server-organizations-api.md); [its evidence](docs/verification/nma-079/README.md) retains the backend/native boundary. See [user authentication](docs/architecture/user-authentication.md). See [persistence and cutover](docs/architecture/postgresql-persistence.md). ACP is an optional transport, not a requirement for a generic runtime registry. Hermes and additional harnesses remain deferred; there is no legacy runtime fallback.

Subscription and API-key billing remain distinct. Use only the selected connection; never silently switch billing. The accepted NMA-050/NMA-060 scope verifies ChatGPT subscription and explicitly selected Muse API-key billing. Muse subscription remains unverified. Missing or unsupported capability is represented honestly, with actionable errors and redacted diagnostics.

The retained single-owner baseline shares one persistent local Linux desktop through Cua SDK → cua-spacesd → Driver. NMA-076 adds [separate retained execution domains](docs/architecture/execution-domains.md) per organization/user for scoped file/Computer access. Browser, terminal, working files and attachment copies resolve to that same authorized domain. Foreground input has one agent-or-human lease per domain; terminal processes may run concurrently. Authorized agents of the same human may cooperate within their domain. Private history, memory, provider credentials and immutable artifact bytes remain in the backend. NMA-079 verifies normal scoped native admission; client UI and deployed transport keep their later gates. See [architecture and trust boundaries](docs/architecture/overview.md).

Composio supplies app connections. Application skills and inherited harness skills are separate: agents create/repair only app-owned packages. Source availability does not promote an upstream feature into scope.

## Optional and deferred work

The [83-row decision register](docs/product/feature-decisions.md) retains every selected decision and note. The owner-operated server, account login and organization access model are promoted by the November 12 plan. Other optional work requires an explicit promotion before becoming an acceptance commitment: advanced CLI editor, managed harness updates, full connection/usage dashboards, context meter/cross-thread search/fork UI, temporary subagents, webhooks, image/document generation and app previews.

The November 11 owner request promotes a web/Tauri Marketplace screen: Plugins/Skills discovery, search and detail, an entry above Settings using `Store02Icon`, direct plugin installation and management with scoped skill availability. Plugin detail has one `rounded-sm` (4px) `Install plugin` action that directly starts the existing connection API; OAuth status, access grants and Uninstall stay in Marketplace. Settings no longer manages plugins. Curated skill ideas prepare a conversation draft rather than installing a package. See [Marketplace behavior](docs/product/interface.md#web-and-tauri-marketplace--2026-11-11).

Deferred work includes additional runtimes, local model endpoints/managers, agent import/export, public marketplace package installation/publishing/payments, voice, external messaging channels, multi-human shared group chats, arbitrary remote/multi-host enrollment and platform hosting/billing services. The new server login/multi-user scope is planned; historical single-owner evidence does not establish its privacy or readiness.

The Tauri macOS ARM64 host is the active implemented development desktop application. A separately authorized GPUI visual/interactivity experiment lives in `apps/gpui-experiment`; it has fixture-only conversation state and no application lifecycle authority. The user-requested [NMA-066–071 desktop-rs plan](docs/architecture/desktop-rs-plan-2026-11-07.md) targets the current desktop's visual and behavioral parity. [NMA-066](docs/backlog/NMA-066.md) and [NMA-067](docs/backlog/NMA-067.md) are **Done** for the implemented native foundation, avatar, composer, messages and rich-content/document components. The [2026-11-08 owner decision](docs/development/nma-066-067-closure-2026-11-08.md) accepts remaining technical verification as non-blocking; [foundation](docs/verification/nma-066/README.md) and [component evidence](docs/verification/nma-067/README.md) preserve actual results and limitations. NMA-068 is Done for the implemented native workspace/conversation with bounded native/API evidence; NMA-069 is Done for native Detail/Library, in-place Settings, Working files and Focus with [bounded native/API evidence](docs/verification/nma-069/README.md); NMA-070 is Done for native Computer/host lifecycle with [bounded evidence](docs/verification/nma-070/README.md); NMA-071 is Done for integrated native development acceptance under the focused November 9 scope. The backend keeps application lifecycle authority. General native-client distribution, other platforms, fresh-device installation and production readiness retain their separate gates; this closure does not complete NMA-063/NMA-064 or authorize removing the existing host.

The November 9 native conversation refinement authorizes find within loaded public messages, improved reference completion and FIFO queue presentation, and a searchable model selector with local favorites. This is a scoped promotion of conversation find; cross-thread/full-history search remains optional. See [native conversation tools](docs/product/interface.md#native-conversation-find-composer-and-model-selection).

Further desktop-rs work is paused by the November 12 owner instruction. Its retained Rust/GPUI rendering contract and NMA-066–071 Done evidence remain historical for their accepted scope; they are not prerequisites for the web/Tauri server-organizations delivery and do not authorize deleting that implementation.

## Delivery and data

Delivery order remains backend → verified API → UI → product acceptance → installation. NMA-072–078 implement the new backend; NMA-079 verifies its API before NMA-080 web/NMA-081 Tauri, NMA-082 deployment recovery and NMA-083 focused integrated acceptance. NMA-063 then owns full-product acceptance and NMA-064 fresh-device distribution. The local backlog preserves 16 completed earlier active milestones and the separate six historical desktop-rs milestones. A later API delta must be verified before UI consumption; prior acceptance covers its captured scope only.

Historical development data may be reset when needed without a compatibility migration. Limit any reset to the authorized development scope and preserve unrelated work. New-runtime persistence, crash recovery and isolation remain mandatory during ordinary operation. Unknown external outcomes require reconciliation before replay. Rollback uses Git and verified backups.
