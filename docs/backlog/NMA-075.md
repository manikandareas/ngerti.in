## Objective

Share authorized Team-agent configuration while keeping each person's conversations, memory, artifacts and event delivery private.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. The [verification report](../development/history.md#verification-archive--2026-11-17 "Archive: docs/verification/nma-075/README.md at 043f7c9") records the completed backend data-boundary scope and its remaining native/UI delivery gates. Targets are the server, web-client and Tauri; desktop-rs source was retired on November 15.

## Owner amendment — 2026-11-14

The default agent uses a random library-generated, single-syllable name rather than a fixed Tobi display name. Retain existing agent identities and names. The internal legacy system-role marker remains a compatibility identifier, not a required display name.

## Implementation units

1. Add organization scope and personal-versus-organization agent ownership, workgroup invocation grants, management permissions and private user preference overlays.
2. Apply the guarded legacy-owner scope mapping after NMA-073/074. Replace shared per-agent personal DM assumptions with user/organization-aware conversation/native-binding contracts and idempotently materialize membership provisioning into one private default agent/DM. Keep existing single-human multi-agent groups within the acting user's scope.
3. Apply access context to every list/get/write, command receipt, search/retrieval, preview/extraction, download, Goal/Routine and replay path; inventory derived caches as well as source entities.
4. Implement tenant constraints/indexes and PostgreSQL RLS under a non-owner application role with transaction-local tenant/actor settings. Bound cross-organization service operations explicitly.
5. Implement server-filtered snapshots/history/SSE and context-bound cursors, permission-change reconciliation and safe per-user organization switching. Publish shared knowledge only through an explicit authorized operation.

## Acceptance criteria

- [x] Two people using the same Team agent cannot retrieve each other's private facts, transcripts, uploads, parsed chunks, previews, saved outputs or receipts.
- [x] Owner/Admin can manage a Team agent but gain no implicit read permission for another person's private conversation; member personalization cannot rewrite shared instructions.
- [x] Personal agents and default agent/DM bootstrap are organization/user private and idempotent; legacy scope is backfilled before multi-user access; Team agents survive creator offboarding and unauthorized Workgroup membership grants no invocation.
- [x] Cross-tenant composite references and uniqueness constraints reject mismatches; RLS is tested using the actual application role and across pooled connection reuse.
- [x] Every affected entity/query/stream/tool surface has a positive and negative access test, including cursor replay after permission changes and handoff/review/routing that cannot exceed the initiating user's grants.
- [x] Concurrent tabs in different organizations and retry after a switch preserve original command scope; private context is never promoted automatically to shared knowledge.
