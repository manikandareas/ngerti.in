# Checklist implementasi perilaku Hermes di Ngertiin

Rujukan perilaku memakai Hermes Agent v0.23.2 di [indeks riset](README.md). Gunakan satu laporan dashboard untuk menetapkan hasil awal. Setelah itu, prioritaskan agent yang belajar dari pekerjaannya, melanjutkan tanggung jawab berdasarkan bukti, dan memilih cara eksekusi sesuai keadaan. Ngertiin memegang admission, antrean, persistensi, kontrol, dan recovery. Harness yang dipilih menjalankan model dan tool loop. [Pemetaan implementasi](ngertiin.md).

Bukti acuan Desktop tersedia untuk loop self-learning, Goal, Cron, Heartbeat, Loop, memory, tools browser dan artifact. Pakai hasil itu sebagai pembanding di sisi Hermes, lalu jalankan skenario Ngertiin pada item masing-masing. [Runtime Hermes Desktop](desktop-runtime.md).

## Cara menjalankan checklist

1. Ambil item terbuka paling awal yang bisa dikerjakan. Baca referensinya dan periksa jalur Ngertiin yang sudah ada. Jika perilakunya sudah tersedia, langsung verifikasi.
2. Implementasikan gap pada jalur normal pengguna. Uji lewat **computer use** di browser atau Tauri yang terhubung ke API Ngertiin. Untuk channel lain, gunakan permukaan pengguna yang relevan, seperti inbox, browser, atau workspace tujuan. Pakai data dan akun uji untuk efek eksternal. Jika perlu menyimulasikan kegagalan, picu dari lingkungan uji lalu lihat hasilnya sebagaimana pengguna melihatnya.
3. Centang hanya setelah hasil dan kasus gagal yang tertulis pada item teramati. Untuk klaim lintas harness atau surface, catat hasil masing-masing yang tercakup. Pemeriksaan kode, API, atau receipt boleh melengkapi observasi jika efeknya sulit dilihat langsung.
4. Tambahkan satu baris di bawah item yang lulus, misalnya `Bukti — 2026-11-18 · Tauri/Codex · satu alert, CSV 12 baris, reload tetap satu alert`, lalu sertakan tautan ke rekaman. Jika terblokir, biarkan kosong, catat penyebabnya, dan lanjut ke item independen. Saat mulai lagi, baca checkbox dan buktinya dari file ini.

## 2. Self-learning dan memory

### Dari pengalaman ke skill yang dipakai kembali

[Learning](learning.md) · [Skills](skills.md) · [Tool learning Ngertiin](../../apps/server/src/learning/tools.ts) · [Scheduler Ngertiin](../../apps/server/src/background.ts)

Hermes memicu review terbatas setelah turn yang memenuhi syarat. Ia mencari fakta tahan lama dan cara kerja yang terbukti, lalu membuat atau memperbarui memory dan skill sesuai scope. Di Ngertiin, laporan DM yang selesai dengan artifact terverifikasi dapat memicu review terisolasi setelah settlement. Pengaturan awal review mengikuti koneksi dan model run asal. Pengguna bisa memilih akun dan model review pada harness yang sama. Review menyimpan fakta dan revisi dalam scope yang sesuai serta mencatat run sumber. Chat baru dengan agent yang sama dapat menemukan prosedur aktif dari katalog skill. Ambang per jenis review dan kasus lifecycle lain dilacak pada item masing-masing.

Untuk pembuktian pertama, gunakan dashboard RUN-01 dengan dua dataset yang berbeda. Minta hasil bisnisnya saja. Pada dataset pertama, biarkan agent menemukan cara yang berhasil menghadapi hasil berpaginasi atau kegagalan ekspor. Setelah review otomatis berjalan, buka percakapan baru dengan agent yang sama dan pakai dataset kedua. Periksa hasil baru, versi skill yang dipakai, dan apakah pola kegagalan dari run pertama terulang.
