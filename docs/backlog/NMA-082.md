## Objective

Provide a reproducible owner-operated central server setup with PostgreSQL, supported harnesses, private execution domains, secure ingress and verified recovery.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record defines the delivered scope and links its separate deployed and historical evidence. Targets are the server, web-client and Tauri; desktop-rs source was retired on November 15.

## Implementation units

1. Pin the supported server OS/architecture, Bun/dependencies, PostgreSQL image/patch, Codex/Muse executables and Cua image/service tuple; prove native compatibility on that target.
2. Provide a reproducible deployment/configuration path for application, PostgreSQL and execution-domain services, with private storage, readiness and operator bootstrap.
3. Configure HTTPS proxy/SSE/uploads/viewer upgrades, trusted origins/proxies, limits and restricted control/database endpoints. Document URL/callback/certificate configuration.
4. Implement and rehearse coordinated database/blob/credential/domain-volume backup and restore, cutover/rollback, migration upgrades, redacted diagnostics and declared RPO/RTO.
5. Document optional VPN/Tailscale as operator-owned infrastructure, plus measured domain capacity, admission and operational health without adding a VPN SDK.

## Implementation delivered — 2026-11-15

The owner selected the existing `mamvps` Ubuntu 24.04 AMD64 host and `https://demo.ngerti.in`. The [runbook](../architecture/server-deployment.md) and [shared-host profile](../../infra/server/shared-host/README.md) preserve its existing Dokploy/Traefik applications while creating a fresh private application stack: LUKS2 storage, a dedicated Docker/containerd pair and network namespace, private PostgreSQL, account-only backend, pinned native Codex/Muse and isolated Cua domains. The earlier ARM64 disposable profile and evidence remain separately retained; the final runtime delta was physically reverified on AMD64.

The actual Owner verified email through Resend and signed in on web and Tauri. The selected existing application-managed Codex subscription authority and Muse API key complete real file/Computer/artifact work before and after cold recovery. Native external-email navigation, selected-thread history and pinned Bun media shutdown have focused regressions. Cua uses attested ephemeral `/run` storage and requires desktop capability before publishing domain readiness; both retained homes survive explicit recreation and repeated restart.

Encrypted operator backup/verify/restore covers PostgreSQL, events/receipts, immutable/provider state, configuration and private domain homes. The actual cold drill returns an off-host Mac ciphertext to fresh empty engine/database/state roots, matches all 42 restored table fingerprints, reconciles Owner/membership and newer tombstones offline, and rotates actual Codex access/refresh tokens without changing account or billing. Previous infrastructure and unrelated work are retained. The final snapshot and independent key verify on the Mac.

## Acceptance criteria

- [x] A fresh private stack on the declared existing Ubuntu host starts the documented configuration and supports actual remote web/Tauri access over certificate-validated HTTPS. This does not claim reprovisioning the host OS.
- [x] Database, harness and Cua control endpoints remain private; public sessions and issuing-device viewer grants are exercised. Optional VPN use retains those controls; VPN enrollment itself is untested.
- [x] Both required native adapters perform useful deployed work and execution-domain isolation is exercised. Protocol/catalog proof remains separate from inference and product-tool proof.
- [x] A real restore recovers consistent database events/receipts, artifacts, native provider authority and working data without cross-tenant reassignment; actual token rotation and both useful native lanes pass afterward.
- [x] Upgrade failure and rollback are rehearsed with preserved data and one lifecycle authority. Coverage includes the retained bounded pre-data rollback/full-snapshot cohorts and actual named-domain recreation; arbitrary schema downgrades remain unsupported.
- [x] Runbook records exact software/source, measured two-domain workload/admission, off-host snapshot RPO and scoped cold-recovery RTO. Fresh-VPS provisioning/unlock, automatic PITR/scheduling, broader load and other platforms remain explicitly unverified.
