## Objective

Deliver the planned multi-organization product in the existing web-client conversation interface using the verified backend contract.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record tracks the accepted web-client scope; the verification report below retains its implementation evidence. The shared UI targets web-client and Tauri, with remote Tauri sessions verified separately in NMA-081; desktop-rs is paused.

## UI direction — owner amendment, 2026-11-14

Keep the interface clean and reduce cognitive load. Retain conversation-first navigation, expose administration in permission-aware Settings, disclose secondary controls only when relevant, and remove repeated headings or explanatory components that do not help a decision.

## Implementation units

1. Implement guarded first-owner setup, web login/recovery/invitation acceptance and immediate private default-agent workspace with a library-generated single-syllable name, preserving creation through unavailable AI setup.
2. Add organization switching, My agents/Team agents and permission-aware Settings for members, Workgroups, Team-agent access and connection ownership.
3. Implement private per-user/conversation AI connection selection and clear actual account/model/billing status; keep app installation/grant management in Marketplace.
4. Namespace and reconcile all retained drafts, uploads, pending commands, projections, search/preview caches, SSE cursors and viewers by server/user/organization/conversation.
5. Preserve existing conversation-first navigation, icons, Focus, contextual panels, queue/stop/HITL, Goals/Routine and progressive personalization; build real API error/loading/revoke/empty states.

Contract amendment: [2.1.0](../contracts/2.1.0.json) adds the verified current-choice projection `GET /v1/data/access` so administrative visibility is not mistaken for agent/connection invocation permission. See the [implementation and verification report](../verification/nma-080/README.md).

## Acceptance criteria

- [x] Owner creates two organizations; an invited Member joins the intended organization with the assigned role/Workgroups and completes a first task without a mandatory personalization wizard.
- [x] Two members see the allowed Team agent and their own private conversations/memory/files; administration controls do not reveal another member's chat.
- [x] Organization/account/server switching across tabs, logout and pending submissions cannot send or display another scope's data.
- [x] A connection change is private to that user/conversation, current billing is visible and an unavailable selection requests explicit action.
- [x] Real API desktop/mobile browser journeys cover creation, invitations, settings, Marketplace, files/Computer, responsibilities, reconnect and removal.
- [x] Accessibility, focus, responsive states and screenshots are assessed on rendered surfaces; existing unrelated conversation behavior remains verified.
