## Objective

Establish the new server-organizations scope through real web/Tauri journeys and authoritative backend/native evidence before the full-product gate.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Run the declared actor matrix: two organizations, three people, distinct roles/Workgroups, one cross-organization account, personal/Team agents and outsider denial.
2. Exercise private chat/memory/derived files, published knowledge/skills, personal/organization AI and app connections, and organization/server/account switching with retained state.
3. Exercise queue/steer/stop/HITL, scheduled responsibilities, revoke/remove, in-flight effects, viewer transfer, server restart and lost acknowledgement.
4. Combine real browser desktop/mobile, actual Tauri, PostgreSQL and native provider/Cua observations with exact source/config/version manifests.
5. Record observed latency/resource capacity on a declared concurrent workload, unresolved limits and adoption/upgrade notes; reconcile all scope and acceptance documents.

## Acceptance criteria

- [ ] NMA-080–082 and their backend/API prerequisites are complete; all affected surfaces and journeys have explicit pass/fail/skip/unknown denominators.
- [ ] Same-agent cross-user and cross-organization privacy holds for transcript, memory, uploads/derived data, artifacts, native sessions, credentials and machine access.
- [ ] Member removal/revocation fences queued and late work, active viewers and data delivery, while preserving authoritative receipts for unknown external effects.
- [ ] Connection selection, effective billing and native refresh are proven without automatic fallback; Codex and supported Muse evidence remain distinct.
- [ ] Web desktop/mobile and actual Tauri remote clients survive switch/reconnect/relaunch; client Quit does not stop central responsibilities.
- [ ] The acceptance report updates product/API/backlog evidence without claiming production capacity, provider entitlement, desktop-rs parity or fresh-device distribution.
- [ ] NMA-063 remains the full-product acceptance gate and NMA-064 remains the fresh-device distribution gate; this milestone reports only its new server-organizations scope.
