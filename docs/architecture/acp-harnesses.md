## Process and attempt identity

ACP wire v1 does not guarantee a provider turn identifier. A run's persisted dispatch token and authority epoch remain authoritative. Correlated session updates or a call to its immutable tool endpoint can establish observed processing. A lost acknowledgement remains unknown; history replay cannot reconcile effects.

Each ACP execution process receives one tool endpoint for at most one application run. Discovery is allowed before dispatch, but effects require an active immutable lease. The endpoint is revoked and the process tree drained at settlement. A subsequent run explicitly loads the authorized ACP session with a new endpoint and process generation. No process can learn a future run's tool credentials.

Artifact publication follows the same application authority. It requires a running bound dispatch and current workspace/grants; a nullable provider turn ID cannot block authorized output. Artifact provenance retains null rather than inventing a turn identity. The later native-context cohort found and corrected the old publication guard, then verified actual output bytes and scoped downloads.

## Simplification and interaction latency

Use SDK operations/configuration/updates directly wherever a local wrapper adds no product behavior. Delete replaced protocol parsers and redundant execution state machines at cutover. Prefer negotiated ACP controls and native interactions to artificial capability restrictions; retain FIFO only when the selected peer cannot safely steer. Native plans do not create Goals or another scheduler. Do not add a universal approval or initiative restriction.

Audit preparation, model discovery, first visible output, tool-response delivery and cancellation against actual timings. Reuse or prewarm non-inference setup when it preserves frozen selection and attempt isolation. Process rotation is required while immutable old-turn correlation is unproven; optimize its preparation rather than giving an old process future tool privileges. Preserve bounded streaming, immediate terminal/history flush, explicit account/billing and durable unknown-effect handling.

Implemented backend slices use one SDK session and projector across the profiles. A new run reuses an unused discovery session instead of reopening it; a resumed run receives a new immutable endpoint/process. Codex retains an account-wide native catalog hook, including per-model reasoning/modalities, rather than replacing it with one session's projection. The first text snapshot is immediate; subsequent text snapshots coalesce within 40 ms, flush before ordered tool/progress events, and flush immediately on terminal response or transport failure. The burst fixture covers 200 chunks and trailing output before settlement; this is not a provider latency benchmark.

Steering uses the negotiated `_meta.steering.supported` extension and `_session/steering`, with `idleBehavior=promptRequired`. A nullable native turn ID no longer blocks it. Durable controls capture dispatch token/authority epoch, check the existing active writer, and restore FIFO on a definite idle rejection. Lost acknowledgements stay unknown. Only the app may admit a later turn.

ACP form elicitation projects string/number/integer/boolean/enumerated multi-select fields into the existing durable question journal. Responses validate required fields, types, bounds and native enum values; decline/cancel never fabricate an answer. Only active session-scoped forms are advertised/accepted. URL/auth elicitation, request-scoped setup prompts, future schema types and agent-supplied regex constraints remain unsupported explicitly; no silent schema downgrade occurs. The web/Tauri consumer uses the verified 2.3.0 delta. Actual desktop/mobile browser and native Tauri journeys cover typed bounds and native-value submission through real HTTP/PostgreSQL with the official SDK subprocess fixture.

Native progress is one bounded run projection: plans, context/cost observations, command discovery, compaction updates/summaries, and workspace-relative file previews. Plans do not create Goals. Tool inputs/results, thoughts, native paths outside authorized roots and opaque metadata remain private. A diff preview is not an artifact or download grant. DM progress offers advertised `compact`/`review` actions through the composer and normal admission. Other native commands or unadvertised context commands are rejected before dispatch. Account/provider/model/tool changes remain app-owned; group command shortcuts require a separately attributed admission path.

Transport replacement creates a distinct ACP session/binding, records `replaces_binding_id`/`replacement_reason`, retains prior run/binding receipts, and supplies bounded settled conversation context. Active/unknown work prevents replacement. Old native session IDs are not silently imported into ACP. Codex ACP execution uses a separate private `acp-execution` home; the retained account authority remains outside that execution process.

Actionable OpenCode quota retries are explicit failures instead of unobserved multi-hour waits. The pinned public event hook bridges only known quota reasons through bounded, private process-bound records; ordinary stderr is diagnostic only. The application returns `PROVIDER_LIMIT`, keeps the selected connection/billing, revokes the run lease and drains the owned process/SDK frames. Transient native retries remain harness-owned. Pi terminal mapping uses the final authoritative native assistant stop reason at settlement, preventing an invalid credential from producing an empty successful run. These hooks do not introduce another prompt loop.
