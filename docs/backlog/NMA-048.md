## Tujuan

Menyediakan kontrak adapter bersama untuk dua runtime wajib saat ini, Codex/ChatGPT dan Muse Code, serta koneksi subscription/API key tanpa memasukkan agent loop kedua di atasnya. Kontrak dapat diperluas; implementasi provider tambahan ditunda.

## Dasar keputusan

[🧭 10 · Matriks keputusan fitur · Harness-first](../product/feature-decisions.md) — B01, B02, B03, B04, B06, T02, T03.

## Unit implementasi

1. Deteksi executable dan versi; manifest minimum/tested version, native protocol, capability serta credential/billing source.
2. Normalisasi start/resume/prompt/events/stop/settings dan native identity; kelola proses dan credential context per koneksi.
3. Definisikan produk-tools bridge terstruktur untuk Codex/ChatGPT dan Muse Code. Custom ACP registration/configuration serta runtime tambahan ditunda; advanced configuration UI B07 tetap opsional.

## Acceptance criteria

- [x] Executable supported/too old/missing dapat dibedakan melalui API; minimum version diuji, bukan hanya dicatat.
- [x] Login, model discovery dan completed inference merupakan state terpisah; auth method dan billing source tidak dicampur.
- [x] API key hanya digunakan ketika koneksi itu dipilih; tidak ada perpindahan otomatis dari plan ke billing key.
- [x] Capabilities menyatakan unsupported/unknown secara eksplisit, termasuk steer, resume, media dan compaction.
- [x] Session/process/account/model tidak tertukar pada dua agent atau dua koneksi bersamaan; semua request ke produk-tools membawa scope yang diverifikasi.
- [x] Lifecycle error, terminal status dan secret redaction memiliki contract tests tanpa UI.
