## Objective

Replace the installation-wide cooperative desktop as a multi-user boundary with enforced private execution domains and scoped Computer access.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Implement a durable resolver for lazy retained Cua environments keyed by organization/user, with lifecycle states, capacity admission and explicit operator setup.
2. Isolate writable volumes, browser profiles, process namespaces and control credentials across domains. Keep host homes, backend state, provider homes and Docker socket outside agent environments.
3. Bind workspace files, attachment materialization, terminals, browser targets, immutable publication and native instructions to the resolved domain; preserve per-conversation provenance.
4. Scope viewer tickets, files roots and human input leases to user/session/domain/generation. Revoke active media and input, not only future ticket issuance.
5. Prove both adapters cannot use host-native work-file writes as an isolation bypass. Preserve within-one-human cooperative machine semantics and document its limit.
6. Exercise lazy provisioning, restart/reattach, missing-domain recovery, concurrent domains, resource limits and safe teardown without replacing a retained machine silently.

## Acceptance criteria

- [ ] An agent with shell access in one domain cannot read another user's/organization's working files, cookies, browser session, process data or control credentials.
- [ ] Working files, terminals, uploads and Computer refer to the same authorized domain and actual bytes; private artifact downloads stay immutable.
- [ ] Cross-domain ticket replay, media upgrades, clipboard/files RPCs and stale human lease revisions are rejected; logout/removal closes existing affected connections.
- [ ] Two required harnesses perform useful scoped file/tool work while host/provider secrets remain inaccessible; unsupported enforcement fails visibly.
- [ ] Restart retains intended domains and data, and stopping one run/client leaves other users' work alive.
- [ ] Resource observations and admission behavior are measured on the declared host; a single shared sudo-capable OS or folder prefixes are not reported as cross-user isolation.

## Verification and evidence

Native Cua probes across at least two people and two organizations, file/browser/process isolation, viewer revocation/lease races and restart/capacity tests.

At implementation time, retain a report under `docs/verification/nma-076/` with exact source/config/dependency versions, setup, denominator, pass/fail/skip, unknown outcomes and limitations. Preserve fixture, database, native/provider, browser/Tauri and distribution evidence as distinct proof. No such verification is claimed by this planning record.
