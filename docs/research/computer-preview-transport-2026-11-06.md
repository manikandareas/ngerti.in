## What the native viewer actually exposes

There is **no existing `postMessage` integration** in the inspected viewer entrypoint, `Viewer` or `MediaSession`. `Viewer.status()` updates the root's `data-status` (`connecting`, `streaming`, `reconnecting`, `failed`). Its `window.__cuaViewer.stats()` test hook exposes decoded-frame counters and `lastFrameAt`. That hook appears only after successful startup and is an internal compatibility surface, not a public product API. The viewer's failed-state Reconnect button reloads its page. [Viewer source, status and hooks](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/viewer.ts#L778-L873).

`MediaSession` declares `streaming` on **`session_opened`, before the first rendered frame**. Its `onFrame` callback runs after successful canvas drawing; counters distinguish received frames from decoded frames. Consequently iframe `load`, WebSocket `open`, and native `streaming` are insufficient individually to claim a visible live preview. [Session and frame callbacks](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/core/mediaSession.ts#L409-L422), [frame drawing](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/core/mediaSession.ts#L537-L559).

For health, protocol `get_stats` returns `frames_since_attach`, `last_frame_age_ms` and `target_idle`; **zero fps can be a healthy unchanged desktop**. The server replies when asked, but stock `MediaSession` does not expose a `stats` message callback. Native WS heartbeat pings every 20 seconds and times out after 60 seconds; it cannot prove that the browser decoded a frame. [Health contract](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/proto/MEDIA.md#8-health-counters-f9), [get_stats handler and values](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua-spacesd/crates/cua-spacesd-session/src/media/viewer.rs#L806-L810), [WS heartbeat](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua-spacesd/crates/cua-spacesd-desktop/src/grpc/media_ws.rs#L133-L189).

## Reconnect and credential rollover

Native reconnect already waits **1,500 ms**, with **20 consecutive failed attaches** before failure. It reattaches with the same media ticket while valid, then calls `OpenMedia` through its `reopen` callback. `4401`, `4400` and `4500` reopen; `4404`, `4410` and `4429` end; `1000` stops. Other/network closures reattach or reopen according to ticket expiry. [Reconnect implementation](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/core/mediaSession.ts#L139-L141), [retry loop](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/core/mediaSession.ts#L340-L390), [close-code decisions](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/core/mediaWire.ts#L246-L275).

Upstream explicitly separates **detach** from **CloseMedia**: disconnecting a socket does not close its media session. Ticket expiry limits new attaches, while an attached socket can continue. There are up to **8 sockets per session** and **64 sessions per driver**. [Media lifetime](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/proto/MEDIA.md#2-ticket-authentication-f3-f4), [limits](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/proto/MEDIA.md#11-limits), [session reap after expiry while unattached](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua-spacesd/crates/cua-spacesd-session/src/media/session.rs#L1660-L1705).

The inspected Ngertiin baseline instead closes peers with `1008`, terminates them and calls `CloseMedia` on **every** `closePeer`. This destroys the upstream session the native client intends to reattach. Its frontend renewal also clears the current view and remounts an iframe keyed by a fresh viewer ID. [Gateway](../../apps/server/src/machines/view.ts), [current viewer component](../../apps/web-client/src/features/conversation/components/machine-viewer.tsx).

**Recommended server change:** renew the existing opaque gateway viewer record in place. Keep its ID/base URL and live iframe; mint a new upstream viewer credential, replace the record's ticket and extend its expiry only while owner, machine generation, grant and control revision still match. Existing proxy code strips client auth and inserts the record's server-held ticket, so the iframe's captured/sessionStorage credential need not change. Native media tickets remain separate and the native reopen callback uses the stable gateway URL. Revalidate the same live record after awaiting issuance; a concurrent revoke, expired grant or changed revision must never be resurrected. [Current credential substitution](../../apps/server/src/machines/view.ts), [native endpoint/auth capture](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/web/src/api.ts#L69-L143).

Transport-only detach should preserve the session for bounded reattachment and retain native close semantics. Explicit release, viewer expiry, ownership change and generation change must still close media/revoke input immediately. Keep bounded media bookkeeping and prune superseded/expired detached sessions; renewal must not leak sessions toward the upstream limit. Unknown CloseMedia outcomes still require existing control-reconciliation behavior.

## Integration recommendation

1. Keep native viewer, codecs, frame acknowledgements and input sequencing. Add one versioned, minimal integration bridge rather than a replacement decoder or a second connection stack. Preferred durable seam: explicit status, rendered-frame and stats callbacks in a pinned viewer adaptation. A same-origin shim may observe root status and the pinned stats hook initially, but must fail visibly if those internals disappear and must not claim full capture-health detection without protocol stats.
2. Send only safe bounded health data to the parent: protocol version, viewer ID, generation, control revision, connection phase and sampled rendered-frame/stat counters. Validate `event.origin`, `event.source === iframe.contentWindow`, shape and current identity. This signal is UI telemetry, never an input grant. Serve an **external same-origin script**; the native CSP disallows ordinary inline scripts. Preserve the existing narrow `frame-ancestors 'self'` adaptation and other CSP restrictions. [Exact native CSP](https://github.com/trycua/cua/blob/38df3cd7c037ce9cea93149984c13ded83e9985e/libs/cua/crates/cua-spacesd-html5/src/lib.rs#L37-L40).
3. Put renewal/retry/subscription ownership above card/panel lifetimes. Use separate stable viewer grants/media sessions for simultaneously visible card and panel unless shared-session reference counting is explicitly implemented. Sharing one revocable viewer ID lets one component's DELETE break its peer. Do not describe separate sessions as one shared browser media stream; upstream support for multiple sockets does not make the existing frontend share a canvas/decoder.
4. Keep the last canvas while reconnecting, marked Reconnecting; stop calling it Live until health recovers. A completed activity removes the preview and renders its compact history bubble. Never infer connection failure from frame age alone or renew stale interactive authority for visual continuity.

## Required acceptance before claiming stability

Verify the actual compiled asset revision/hash and bridge contract; first decoded frame; static healthy desktop; media loss and recovery; unavailable host; repeated failure/backoff; credential renewal beyond ten minutes with **unchanged iframe element**; renewal/revoke races; expiry while disconnected; backend restart; concurrent card/panel plus independent unmount; hidden/visible transitions; takeover/handback with stale-input rejection; and no leaked viewer/media resources. Record these independently from SDK import, service health and old native UI evidence.

## Implementation follow-up

The source implementation and subsequent live verification are recorded separately in the [2026-11-06 delivery report](../verification/conversation-implementation-2026-11-06/README.md). That work started the retained machine and exercised native decoding, renewal and transport recovery; the read-only research boundary above describes this investigation itself. Close code `1000` is terminal/intentional in the pinned viewer, while a transient test can use server `1011` or client `4001` (the browser disallows `WebSocket.close(1011)`). Do not call `Viewer.start()` repeatedly as a recovery shortcut. Preserve native reattachment; terminal/unresponsive recovery may replace the viewer grant without restarting the machine.
