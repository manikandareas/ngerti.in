## Objective

Offer authorized Team/default and personal model-provider connections without changing another user's agent settings or moving harness execution to client devices.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. The [implementation contract](../architecture/provider-connections.md) and [verification report](../development/history.md#verification-archive--2026-11-17 "Archive: docs/verification/nma-077/README.md at 043f7c9") retain the verified backend and native proof, including two distinct live ChatGPT accounts, one Free. Targets are the server, web-client and Tauri; desktop-rs source was retired on November 15. This completion covers provider connections; production organization native admission still requires NMA-078 app/MCP/skill isolation.

## Implementation units

1. Add explicit connection ownership/access and private per-user/conversation selection. Resolve only unset preferences through defaults; validate harness/model/effective billing compatibility.
2. Freeze connection identity, generation and account/model on admitted work; extend native binding and resume keys with organization and actor identity.
3. Integrate and prove supported remote/headless Codex login from a browser on another device; retain Muse API-key support and honest unsupported/unknown subscription states.
4. Separate connection credential authority from actor/binding-private native HOME/CODEX_HOME/session storage. Harden at-rest volumes/backups, coordinated refresh persistence, log redaction and private process environments; prove a supported credential-delivery mechanism rather than copying entire native homes or racing stale token copies.
5. Implement disconnect/revoke/rotation and active-process/session retirement with explicit treatment of residual native auth files and provider-side revocation limitations.
6. Bind Goals/Routine to a durable principal and selected connection so execution never borrows ambient UI identity. Record requesting actor and actual connection without exposing secrets.

## Acceptance criteria

- [x] Two people can use one Team agent with different personal connections and native sessions; two users selecting the same organization connection also retain separate native transcripts/history/skill caches and private bindings.
- [x] Only unset selection inherits allowed defaults; an invalid explicit personal selection asks for reconnect or explicit switching and never falls back silently.
- [x] Selection changes affect future work, leave the shared agent unchanged and cannot resume another account's native session.
- [x] A real remote Codex login, catalog, inference and scoped tool result are separately demonstrated; native refresh survives restart using the selected private context.
- [x] Other users, model-visible context, working files, logs, receipts and clients do not receive provider tokens; disconnect and restoration cannot resurrect revoked local access.
- [x] Account/billing attribution and offboarding/scheduled-work behavior are verified; Muse subscription remains unknown unless separately proven on this implementation.
