## Objective

Run the existing application lifecycle on PostgreSQL while preserving atomic state/events/receipts, durable ordering and single-authority recovery.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Inventory Store, conversation journal, all direct SQLite consumers, JSON indexes and synchronous transaction call sites. Pin PostgreSQL and the Bun-compatible pg driver; document the baseline and migration mappings.
2. Implement async transaction-bound persistence with bounded indexed queries, organization/actor-ready keys, nested rollback semantics and migrations. Preserve immutable artifact storage outside SQL.
3. Make event cursor publication commit-ordered under a concurrent writer race. Scope idempotency and reauthorize receipt reads; retain reserved/unknown command semantics.
4. Replace the lifetime SQLite lock with a dedicated PostgreSQL authority lock plus durable epochs. Fence dispatch and publication on lock loss; retain one lifecycle authority.
5. Build a dry-run SQLite import, reconciliation report, verified backup and consistent rollback path. Retain the legacy owner and a mapping manifest here; verified account/organization binding follows NMA-073/074 and scope backfill in NMA-075 before multi-user access. Do not reset live state or copy credentials implicitly.

## Acceptance criteria

- [ ] PostgreSQL boots, persists and replays the current required domain against disposable data, including creation, queue, controls, Goals/Routine, memory and artifacts.
- [ ] Domain mutation, events and receipt roll back together; nested failure, duplicate/concurrent commands, lost acknowledgement and unknown effects preserve their original identities.
- [ ] A smaller event sequence committed later cannot be skipped by a consumer; filtered cursor replay and snapshot consistency are demonstrated.
- [ ] Authority loss/restart and attempted second authority cause no duplicate dispatch; pool reconnection cannot silently transfer a lifetime lock.
- [ ] SQLite import comparison covers IDs, counts, event order, receipts, artifact hashes and native binding treatment, and rollback is actually rehearsed.
- [ ] Meaningful regression results and measured transaction/event latency are retained with exact versions; no claim that SQLite was already overloaded is made.

## Verification and evidence
