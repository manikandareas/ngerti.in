## Objective

Share authorized Team-agent configuration while keeping each person's conversations, memory, artifacts and event delivery private.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Add organization scope and personal-versus-organization agent ownership, workgroup invocation grants, management permissions and private user preference overlays.
2. Apply the guarded legacy-owner scope mapping after NMA-073/074. Replace shared per-agent personal DM assumptions with user/organization-aware conversation/native-binding contracts and idempotently materialize membership provisioning into one private Tobi/DM. Keep existing single-human multi-agent groups within the acting user's scope.
3. Apply access context to every list/get/write, command receipt, search/retrieval, preview/extraction, download, Goal/Routine and replay path; inventory derived caches as well as source entities.
4. Implement tenant constraints/indexes and PostgreSQL RLS under a non-owner application role with transaction-local tenant/actor settings. Bound cross-organization service operations explicitly.
5. Implement server-filtered snapshots/history/SSE and context-bound cursors, permission-change reconciliation and safe per-user organization switching. Publish shared knowledge only through an explicit authorized operation.

## Acceptance criteria

- [ ] Two people using the same Team agent cannot retrieve each other's private facts, transcripts, uploads, parsed chunks, previews, saved outputs or receipts.
- [ ] Owner/Admin can manage a Team agent but gain no implicit read permission for another person's private conversation; member personalization cannot rewrite shared instructions.
- [ ] Personal agents and Tobi/DM bootstrap are organization/user private and idempotent; legacy scope is backfilled before multi-user access; Team agents survive creator offboarding and unauthorized Workgroup membership grants no invocation.
- [ ] Cross-tenant composite references and uniqueness constraints reject mismatches; RLS is tested using the actual application role and across pooled connection reuse.
- [ ] Every affected entity/query/stream/tool surface has a positive and negative access test, including cursor replay after permission changes and handoff/review/routing that cannot exceed the initiating user's grants.
- [ ] Concurrent tabs in different organizations and retry after a switch preserve original command scope; private context is never promoted automatically to shared knowledge.
