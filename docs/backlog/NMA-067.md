## Objective

Deliver the reusable components that carry Ngertiin's identity and difficult editing/rendering behavior before composing live product workflows. Follow the selected rendering paths and [parity contract](../architecture/desktop-rs-plan-2026-11-07.md#parity-contract).

## Implementation units

1. Port recipe parsing/versioning, 32-bit seeded random behavior, body geometry, colors and fur generation to the Rust avatar crate. Separate cached material/texture from dynamic eyes, pose and ornaments. The desktop adapter owns GPUI drawing/input.
2. Port expression/state mapping, idle breathing, gaze/head smoothing, independent blink, actions, loading rings/veins, reduced motion and visibility-aware clocks. Preserve original texture/filter appearance and transparent SVG/PNG export; resolve the experiment's omitted eye-shadow effect.
3. Build the native composer model and view: multiline text, mention/file/skill references, suggestions, cursor/selection, deletion, undo/redo, IME composition, Unicode/graphemes, clipboard/files and focus restoration. Keep editing state separate from submission/network policy.
4. Implement bubbles, attribution, activity, clocks/day markers, question/approval controls, reference/source links, attachment rows and reusable error/retry presentation. Cover user/assistant, DM/group and file-only messages.
5. Implement Markdown/GFM, code, image, CSV/TSV/table, source, PDF and static HTML presentation components. Preserve syntax palette, selection/copy/download, table sorting/filtering/wrapping/expanded view, source find/wrap/line numbers, and the current preview limits. Use the NMA-066-selected native PDF adapter with GPUI interaction/controls. Only the static HTML document body may use the isolated browser adapter; follow the [rendering ownership contract](../architecture/desktop-rs-plan-2026-11-07.md#rendering-ownership-contract).
