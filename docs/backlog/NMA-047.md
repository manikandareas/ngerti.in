## Tujuan

Menjalankan satu lifecycle aplikasi yang tidak bergantung pada Hermes sebagai engine wajib, dengan kontrak data dan API baru yang dapat dikembangkan tanpa UI.

## Dasar keputusan

[🧭 10 · Matriks keputusan fitur · Harness-first](../product/feature-decisions.md) — T01, T04, T05, H03.

## Unit implementasi

1. Audit exact module/flow Openbot dan pilih seam adopsi/port beserta bahasa/proses runtime; tutup ADR implementasi dengan bukti kecil, bukan mengganti arah produk.
2. Tetapkan satu otoritas admission/run/queue/goals/recovery, entity identity dan native-session binding; harness hanya memiliki inner execution.
3. Siapkan dev bootstrap dan storage baru; reset data development diperbolehkan. Bersihkan kode/config/docs/tooling Hermes yang tidak relevan setelah dependensi penggantinya tersedia.

## Acceptance criteria

- [x] Ada satu entry point development yang menjalankan otoritas aplikasi dan persistence dasar; tidak ada scheduler/executor Hermes lama sebagai fallback tersembunyi.
- [x] Kontrak agent/thread/run/message/goal/Routine/artifact, scope owner tunggal, event/cursor, cancellation dan unknown outcome tertulis dan dapat diuji.
- [x] Openbot module/revision/flow yang diadopsi tercatat; pilihan internal runtime/bahasa dibuktikan kompatibel dengan SDK/adapter yang dibutuhkan.
- [x] Keputusan baru tentang authority dan reset development tercermin pada repo guidance/dokumentasi; tidak mengeklaim runtime baru selesai hanya karena ADR dibuat.
- [x] Tidak mengimplementasikan UI atau installer; code reuse relevan boleh dipertahankan dengan batas yang jelas.
