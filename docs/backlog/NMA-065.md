## Objective

Create a persistent agent or group, open the correct conversation, and admit one visible automatic opening message under the human owner. Personalization happens through normal conversation and scoped product tools, without requiring Tobi as an intermediary or a mandatory setup questionnaire.

## Source decisions

[🗺️ 11 · Peta screen dan fitur frontend · Harness-first](../product/interface.md) and [🧭 10 · Matriks keputusan fitur · Harness-first](../product/feature-decisions.md) — A03, C02–C04, D01–D02, D05, E01, F01, H01–H03, H06. This amendment refines selected features; it does not promote optional features or additional runtimes.

## Implementation units

1. Audit and reuse NMA-052/053/055/056/057 contracts. Implement only the missing behavior; record source modules, revisions, and actual gaps before changes.
2. Agent creation uses a maintained random-name library with a recorded version. The backend guarantees owner-scoped name availability under concurrent creation/collisions. Use a default avatar and the user's explicitly selected default connection/model/billing; no model/key fallback.
3. Bind creation, conversation identity, and the automatic opening message/admission to a stable operation identity. Distinguish persisted creation from opening-message delivery, native outcome, and personalization state; separate requests are acceptable if recovery is durable.
4. Group creation accepts a name and selected owned agents. Choose one valid member through the existing context router to lead the opening. Preserve explicit authorship; do not publish pass/skip messages or greet from every member.
5. Provide scoped self-update and group-configuration tools. Agent identity/instructions/preferences remain separate from group purpose/shared instructions and from DM-private resources.
6. Return authoritative creation, opener, configuration revision, capability, and failure/recovery projections/events for the conversation UI and contextual right panel.

## Acceptance criteria

- [x] A create-agent command yields one persistent agent/DM with a library-generated name; concurrent requests and deliberate name collisions do not create ambiguous owner-local names. The naming dependency/version and default-avatar behavior are recorded.
- [x] Repeating a creation operation after retry/lost acknowledgement/reconnect/restart returns the same entity/conversation and does not add an opening message or admission. A distinct intentional create action may create another entity.
- [x] The automatic opener has human-owner authorship plus a traceable app-generated/creation origin and is visible in the transcript. UI localization is supported; backend-authored prompts/messages follow the repository English rule and supplied content is preserved.
- [x] Opening an existing conversation does not create an opener or start inference. Tobi bootstrap/authored welcome remains separate and retains its original idempotent behavior.
- [x] Agent/group creation survives a missing connection, dispatch failure, or failed initial response. Recovery continues the existing conversation; native outcomes that remain unknown are reconciled before retry, without blind replay.
- [x] Default connection/model/billing choices are explicit and capability-valid; unavailable defaults produce an actionable state without silent subscription-to-key billing changes.
- [x] Group creation validates owner/membership at dispatch and produces one opening speaker. Group name/purpose/shared instructions can be updated through scoped tools; private DM history/memory/files and unrelated member profiles do not change implicitly.
- [x] The opening follows the actual user need, asks only a necessary question at a time, and can immediately perform a clear task. Name, role, persona, goals, and working style are examples, not a mandatory checklist.
- [x] Successful agent/group configuration changes produce receipts/revisions/events that update the correct sidebar/panel identity. Group context cannot invoke self-update as an implicit instruction to rewrite every member's global profile.
- [x] Personalization discussion alone does not create active goals or Routine. Genuine responsibility/scheduling requests continue through the existing scoped goal/Routine tools.
- [x] Contract examples, concurrency/replay/restart/failure/privacy tests, and useful native opening plus scoped-update round trips are recorded separately for Codex/ChatGPT and Muse Code, with versions, setup, denominators, failures/skips/unknowns. Existing evidence may be reused only for behavior it actually proves.
- [x] Consumer contracts and NMA-060 coverage/prerequisites include this amendment before UI implementation begins. No frontend features or installer changes are implemented here.
