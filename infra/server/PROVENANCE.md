# Deployment profile provenance

This is a locally authored Ngertiin deployment/operations profile. It reuses the existing harness adapters, PostgreSQL authority/persistence, account contract and isolated Cua runtime; it adds no second lifecycle authority or runtime fallback. No upstream deployment scaffold was copied.

| Input | Exact source and reuse |
| --- | --- |
| Bun | Official `oven-sh/bun` release `bun-v1.3.10`, Linux aarch64 ZIP; artifact URL/checksum in `versions.json` |
| Codex | Official `@openai/codex@0.169.0-linux-arm64` npm artifact; retain the complete vendor resource tree, not just the executable |
| Muse | Official Meta download manifest for `1.4.14-R7309.1`, `aarch64_linux`; manifest checksum `3dc39b8fa26f9963cc2038f2966c0932ed5a39f0f9efb39cc0266a261cbbcf76`; existing SDK pinned at 1.4.14 |
| PostgreSQL | Official 18.1 Alpine image at the digest in `versions.json`; reuse the existing NMA-072 pin, including its PostgreSQL-18 storage layout |
| Caddy | Official 2.11.2 Alpine image at the digest in `versions.json`; local Caddyfile follows the official proxy/body-limit semantics |
| Cua | Existing Ngertiin image `9ac0d6f6f7dd95392554ec95163f83c5061de3db05b64977696c78d71cd4861c`, SDK 0.10.1, observed spacesd 0.8.0 and Driver contract 1; existing startup assets and protocol provenance remain authoritative |

References: [Caddy streaming/WebSocket/header semantics](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [body limits](https://caddyserver.com/docs/caddyfile/directives/request_body), [existing Cua provenance](../../apps/server/src/machines/protocol/UPSTREAM.md), [provider contract](../../docs/architecture/provider-connections.md) and [deployment runbook](../../docs/architecture/server-deployment.md).

Local adaptations: account-only production bootstrap; loopback controls and private run-lease ingress; same-origin HTTPS/SSE/WSS; separate restricted database login; stable operator-owned machine assets; coordinated database/state/trust/domain-home snapshots; streaming authenticated backup encryption and empty-target restore with latest-tombstone union and fingerprint validation. Credentials/configuration and plaintext staging remain private. The operator retains one scheduler/authority.

Upgrade checks: review native CLI/SDK protocol changes and exact artifacts; refresh pins only with platform/native/provider proof; verify database migration/authority/restore, origin/cookie/PKCE and SSE/WSS behavior; preserve retained home/identity and current revocations; rehearse failed startup and full snapshot recovery. Images, unauthenticated handshakes and source availability do not prove completed provider work or billing. The [verification report](../../docs/verification/nma-082/README.md) records limits; license administration remains with the owner.

The owner-selected shared AMD64 host uses `versions.amd64.json`: Bun's official `SHASUMS256.txt` matches its x64 ZIP; the Codex x64 npm artifact also matches the registry's SHA-512 integrity; Muse's pinned release manifest supplies the `x86_linux` artifact URL/size/SHA-256. The original Cua immutable OCI index includes an AMD64 child at `sha256:ec66a0c4dd6252b4dd2f76583b811dedbd6e7afdee4590ae68f11fa784f1d078`; no mutable latest-image substitution is used. The [shared-host adaptation](shared-host/README.md) reuses the existing Traefik file provider while separating encrypted Docker state and network/firewall ownership.

Account HTTP shutdown adapts the existing `elysia@1.4.30` module `elysia/adapter/bun` (`dist/adapter/bun/index.mjs`, `BunAdapter.stop`), pinned by `bun.lock`. The local `organizations/http-adapter.ts` preserves its listener clearing and awaited stop hooks. For forced shutdown on Bun 1.3.10 only, it closes connections, drains actual HTTP requests with a five-second failure bound, and unreferences the stopped listener instead of awaiting the reproduced stale closed-WebSocket counter. Viewer grants/sockets are revoked before that adapter runs. No authentication or transport check is skipped. Re-run the actual authenticated media/shutdown regression, lifecycle hooks, native HTTP/SSE/WSS and database authority checks on Bun/Elysia upgrades; other Bun versions use the ordinary adapter.

The immutable Cua image's `/opt/cua/bin/start-spacesd.sh` waits for `/run/cua-desktop/desktop.env`; `/opt/cua/desktop/start-desktop.sh` writes it after X/DBus readiness. An ordinary Docker stop/start preserves that directory in the writable layer, allowing a stale environment to satisfy the wait before the new desktop is ready. The locally authored runtime adaptation mounts `/run` as bounded 64-MiB tmpfs (`noexec,nosuid,nodev`), attests the exact mount configuration, and requires `desktop_stream` capability before marking an authenticated domain ready. No upstream script or replacement binary is copied, and the immutable image remains unchanged. Existing domains require explicit container/network recreation with their named home volumes retained. Upgrade checks include two-domain recreation, repeated stop/start with stale-runtime marker removal, native desktop capabilities, WSS/video and exact retained working bytes.
