Both actual read checks passed through the product's saved native connections. See [current acceptance and explicit limits](nma-033-minimal-acceptance.md). ## Runtime boundary

Hermes revision `7489b22af47ce91b366dde81d5831ea422577498` remains the sole execution, session, inference and recovery owner. Upstream source is unchanged. `runtime-pin.json` records new seam hashes, MCP SDK 2.3.0, Firecrawl SDK 4.17.0 and Exa SDK 2.10.2. The foundation explicitly installs upstream's `firecrawl` and `exa` extras; runtime lazy installation remains disabled. A new environment was built in `.dev/nma-033/production`. The default local provisioner now selects this environment; existing operators must rebuild and set `NMA_RUNTIME_PYTHON` accordingly.

The Exa wheel and source distribution omit the license file. Its declared MIT notice is supplied from [Exa's upstream license](https://github.com/exa-labs/exa-py/blob/2227b4f95f63e83e162d14c5c086a3210fb769ee/LICENSE), with exact source and notice checksums in `apps/engine/notices/provenance.json`. The packaged inventory is in [runtime-inventory.json](evidence/nma-033/runtime-inventory.json). No missing notices remain in the new local foundation.

`app_runtime.py` expands owner-local connection references at native `session_local_mcp._configs`, retains native schema/result types, and uses native discovery, registry, OAuth worker, PKCE, refresh and token storage. Stable credential generations survive tool-selection changes; credential replacement creates a new token identity. Native OAuth commit persists only a disabled, secret-free profile receipt; a login cannot activate profile-wide tools or create another credential writer. Scoped app configuration remains in the private app journal. The one native MCP loop stays alive until gateway-wide shutdown: upstream idle-loop shutdown otherwise races a newly starting discovery operation. Scoped servers still shut down normally. This is a lifecycle adaptation, not a second loop or scheduler.

`app_interactions.py` captures the actual pending call context for native sampling and elicitation. Sampling uses the calling agent's frozen native model route and credential relay. The server cannot select ambient profile credentials by naming an arbitrary model. Native declared-cost consent and form elicitation become protected owner/thread/run-bound forms. Every answer rechecks execution, capability, connection generation and conversation fences. URL-mode elicitation is declined, matching the unsupported upstream path. Experimental MCP event delivery is unavailable: upstream creates profile webhook routes and currently has no product thread-bound wake bridge. Enabling `events` fails closed with `mcp_events_bridge_unavailable`; it is not counted as delivered.

## Direct research

`research.py` selects native Firecrawl, Exa, Tavily, Brave or SearXNG search and supported Firecrawl/Exa/Tavily extraction. Credentials are owner-local; Nous Tool Gateway and anonymous rescue are disabled through native configuration. Optional xAI public `x_search` has its own readiness and grant. Missing xAI credentials do not disable web research. A configured key establishes setup readiness, not proof of a successful remote request.

Native ranked source URLs, descriptions, provider errors and long-page head/tail truncation are retained. Native search memo keys and extract storage are scoped by owner, agent, thread, context generation and research configuration generation. Long source bytes are copied through the existing signed workspace broker into `/work/imports/web/<sha256>.md`, then published as a scoped file artifact. The model can use native `read_file` pagination on the same bytes. Web grants depend on the native file bundle; no existing agent silently gains these grants.

Durable `research.completed` events record provider, total tool latency, cache lookup hits/misses and failure phase without query or credential values. Native SDK read retries remain authoritative. A source read error is classified as read semantics, while arbitrary MCP calls remain conservatively mutation-capable. No unknown external write is blindly replayed.

## Isolation, setup and API

New version-1 private journals live under `app-secrets`, `app-auth`, `app-interactions` and `research-secrets` in the already isolated owner partition. Files use native atomic persistence/locks and mode 0600, directories 0700. There is no new SQL schema or destructive migration. Existing HTTP MCP grants, IDs, provider connections, histories, goals and files remain readable. App/OAuth/research secrets are not copied into command receipt tables, discovery schemas or model context. Token values and OAuth client secrets are registered with redaction.

Connections do not grant agent access. A user must assign the named connection in Agents. Disconnect and configuration changes fence unfinished work; current frozen configurations cannot acquire new tools implicitly. Remote provider revocation is explicitly unconfirmed. A browser callback uses the actual authenticated Clerk session, native state/PKCE and exact callback path; identical callback delivery is idempotent without another exchange. Interrupted pending browser logins must restart after a gateway restart. Completed tokens retain native refresh behavior.

Stdio invokes only an operator-pinned immutable Docker image and argv. No user-supplied gateway shell is accepted. Containers are non-root, read-only, capability-dropped, resource-bounded and receive only declared app credential environment variables, with no host mounts or model/control credentials. The default network is disabled. Opt-in public egress uses the existing internal-network proxy. Egress state is separated per connection and cleaned at disconnect; owner-labeled orphan stdio processes are removed before recovery. This is the native MCP supervisor's process transport, not an alternative agent executor.

The authenticated `/api/agent-engine/v1/apps` API has no-store responses and supports list/configure, discover, tool selection, disconnect, native OAuth start/status/callback/cancel, pending interactions/answers and research configuration/disconnect. The Connections UI supports named accounts, reconfiguration/reconnect, bearer tokens, native OAuth navigation, tool checkboxes, research keys and forms. Error messages distinguish failed setup and expired/changed authorization.

Operator configuration:

- `NMA_APP_ALLOWED_ORIGINS`: JSON list of reviewed custom service origins. Fixed Notion/Linear/GitHub entries cannot be replaced from the browser. Loopback HTTP is allowed only for explicitly reviewed local fixtures.
- `NMA_APP_SERVERS_FILE`: JSON object keyed by profile, each containing `application`, immutable `image`, `command` argv and `credential_env` references (`api_key`, `oauth_client_id`, `oauth_client_secret`), with optional `public_network`.
- `NMA_APP_OPTIONS_FILE`: JSON object keyed by owner UUID, then connection UUID. Native supported keys: `identity_header`, `client_cert`, `client_key`, `sampling`, `elicitation`, `tool_costs`, `spend_limit`, `cost_unit`. These values are operator-owned and fingerprinted into the grant. Identity/mTLS configuration has not yet been exercised against a real deployment.
- `NMA_GOOGLE_OAUTH_CLIENT_ID` / `NMA_GOOGLE_OAUTH_CLIENT_SECRET`: optional server-only shared Google Web client registration, applied when configuring a Google connection. Equivalent per-connection fields are private and preserved on edit. No server URL or account password is requested.
