## Objective

Prepare `apps/desktop-rs` as a maintainable native GPUI client and establish a reproducible reference before implementing product screens. This is the first step of the [observed six-milestone plan](../architecture/desktop-rs-plan-2026-11-07.md). Its [rendering ownership contract](../architecture/desktop-rs-plan-2026-11-07.md#rendering-ownership-contract) prohibits a WebView-hosted application shell.

## Implementation units

1. Create an independent Cargo workspace with `desktop`, GPUI-independent `client`, and GPUI-independent `avatar` crates. Keep feature views, reusable UI, host/platform integration and local storage separate. Provide build/run/format/Clippy commands and controlled backend attachment for development.
2. Freeze the current Tauri/web-client surface/state baseline, exact revisions/contracts/assets, representative data and native lifecycle behavior. Capture new native references when computer-use access is available; retained screenshots supplement rather than replace this step.
3. Map actual product-used controls and compound widgets to native equivalents. Implement theme tokens, fonts/icons, typed variants/style overrides, focus/accessibility behavior, menus/dialogs, fields, list rows, tabs, scroll/resize and loading/empty/error primitives. Classify gallery-only controls separately.
4. Build a component gallery with state/variant previews and stable capture IDs. Read theme values and original asset provenance from the existing client instead of adopting GPUI Kit's default appearance as product design.
5. Resolve high-risk renderer choices early: composer IME/token selection/clipboard, avatar texture rotation/filter quality, table/source selection and virtualization, PDF selectable text/zoom, static HTML isolation, and native overlay/focus above a child WebView. Minimal proof cases belong here; full components belong to NMA-067 and live Computer acceptance to NMA-070.
6. Establish client contract decoding/error handling and a read-only snapshot attachment. Keep backend lifecycle authority unchanged, native credentials outside embedded content, and test profiles distinct from current Tauri state.

## Acceptance criteria

- [x] The app and gallery launch on the reference macOS ARM64 host; crate dependency direction is enforced and the entry point only composes modules. No full React application is embedded as the new shell. The native gallery launched; its example shares the same composition and is compiled in all-target checks.
- [ ] A versioned parity manifest lists every current product surface/state and source owner, including later Focus/PDF/Working files/chronology amendments. Baseline captures specify viewport, device scale, font, theme, locale/time zone, fixtures and source revision.
- [ ] Product-used foundational controls have light/dark, hover/pressed/focus/disabled, keyboard and accessible-name checks. Existing Geist/Geist Mono, Hugeicons and format-icon provenance is retained.
- [x] Gallery examples demonstrate default + variant + caller override composition. Durable state is owned by Entities; lightweight reusable views use explicit props/callbacks. Feature-specific rules do not leak into generic controls.
- [ ] Each high-risk renderer has an executed proof and a recorded selected implementation path, pinned dependency/source and limitations. An unresolved capability needed for parity prevents this milestone from being Done; full parity is not claimed by the spike.
- [x] Contract version/shape failures, backend unavailable and read-only startup display actionable states. Opening the gallery/reference or an existing thread starts no inference and writes no new domain responsibility. Native success/fault captures and real API cursor checks are retained.
- [ ] Native baseline and performance workloads/budgets are recorded before implementation comparison. Unavailable native access is recorded as an unexecuted check, not a pass.
- [x] Relevant Rust checks, gallery captures, renderer-spike results and source-adoption/upgrade notes are retained. No existing profile, credentials, backend database or retained evidence is reset.
- [x] Source and runtime inspection confirm that the shell, gallery and native PDF proof do not mount React/web-client or a browser-based PDF UI. WebView construction is confined to the selected HTML/Computer adapter. PDF uses PDFKit; only the fixed static HTML proof constructs a WebView in this slice.
