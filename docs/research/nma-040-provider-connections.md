## Product and native integration

The authenticated `/connections` page adds API-key connections, starts browser authentication, polls/cancels/retries a durable login, refreshes models, replaces keys, and disconnects an account. Agent settings expose connected account/model choices and a direct repair link. Clerk remains the product sign-in authority; connecting inference never changes the Ngertiin account.

Tobi provisioning and the authored welcome no longer require an OpenAI key. An account without a provider retains its persistent identity and empty DM, and inference returns an explicit unavailable-model result until a connection/model is assigned. Existing environment-backed catalogs are imported once into their existing owner partition. A new account receives the optional environment bootstrap only when its UUID matches the trusted `NMA_BOOTSTRAP_OWNER_ID`; a global development key is not automatically shared with newly registered owners. Restarting the gateway does not regenerate or overwrite durable connections or the existing model aliases.

Hermes at `7489b22af47ce91b366dde81d5831ea422577498` remains the sole session, execution, scheduling, cancellation and recovery authority. There is no second agent loop, inference abstraction, scheduler, or app-server runtime. Native chat, Responses, and Anthropic transports execute inference and native tool calls.

The narrow trusted credential relay binds to `127.0.0.1`, accepts an HMAC-authenticated frozen route, checks its exact native started admission, run, authority epoch, execution generation and durable stop/revocation fences, resolves only that connection's current credential, and forwards the declared wire. An old route cannot borrow a later admission in the same session, and a route without an admitted execution cannot dispatch. It does not choose a model, switch an account, execute tools, or implement failover. Its connection lock orders disconnect/key replacement against actual upstream dispatch, then releases while streaming. Provider keys are never given to native model/tool workspaces; bootstrap provider key environment variables are removed after owner assignment. Host/container isolation remains the separate NMA-028/027 boundary, not a claim about Unix profile names.

An admission freezes connection, account/registration, credential generation, model, endpoint, protocol and billing context. Replacing a key or reconnecting advances the generation: existing routes cannot silently adopt a different grant. Ordinary authorized token rotation retains the connection generation. Changing an agent or model affects subsequent admissions; original binding/configuration bytes and old receipts remain intact. Historical bindings receive a separate, one-time owner-assignment snapshot.

## Authentication, storage and failure semantics

The owner-local private journal uses pinned Hermes `_auth_store_lock(target_path=...)` and `_save_private_json(..., fsync_dir=True)`: cross-process locks, a protected directory and atomic `0600` replacement. SQLite stores only public connection metadata and non-secret references. Secret-bearing commands bypass the generic command/event journal. A lost metadata acknowledgement is reconciled from the already-committed private journal at restart.

Login state includes the verified product-session binding, owner partition, state, nonce, PKCE verifier, callback URI, expiry and durable outcome. The loopback launch sets a per-attempt HttpOnly SameSite cookie before redirecting to the provider; callback requires that browser binding. OpenRouter also carries its nonce in the callback path to support the pinned contract that did not echo a query state. Cancellation/expiry reject late callbacks; completed callbacks cannot redeem a code twice. Unknown exchange outcomes require fresh authorization, retaining an already-issued registration. A browser on the same host as the gateway is required for this loopback integration; remote/hosted callback deployment is not claimed.

ChatGPT uses the public dynamic-registration endpoints and a stable opaque host ID. JWT validation uses pinned PyJWT/cryptography: signature, issuer, issued-client audience, expiry, nonce and subject. A returning login must match the saved subject and client registration. The issued client ID is the workspace registration boundary; email is never used as identity and an unverified workspace identifier is not fabricated. Only granted inference scopes permit plan use.

OpenRouter's pinned exchange helper returns only the key. The narrow adapter retains the current documented exchange response's `user_id`, permitting a new key grant to reconnect to the same verified provider user. If that nullable identity is absent, the connection is identified as an opaque grant; a different grant cannot silently replace its identity. Workspace identity is left unknown unless actually established. The original native exchange contract and its source hash remain recorded.

One trusted Python writer owns refresh for each connection. Rotation replaces access/refresh credentials and expiry together under the native cross-process lock. A durable refresh intent prevents blindly replaying an exchange whose rotating-token outcome was lost to a crash. Terminal renewal rejection surfaces reconnect. Local disconnect immediately stops future dispatch after its acknowledgement, preserves identities/history, and distinguishes confirmed ChatGPT session revocation from unconfirmed remote removal. OpenRouter key removal is local unless remote revocation was actually confirmed.

Quota/usage limits, entitlement, unsupported model, renewal failure and provider outage retain distinct stable codes. Public Responses streaming success requires the native completed terminal; a failed/incomplete/missing terminal is not a successful result. Native tool/effect receipts, stop fences and indeterminate work remain authoritative; no effectful tool is replayed to repair inference authentication.

## Migration, backup and rollback

Extension schema 14 adds `nma_provider_connections`, `nma_provider_failures`, and `nma_provider_legacy_routes`. It preserves migrations 1–13 and their checksums, all agent/thread/configuration/history/goals, and old immutable bindings. Startup fails closed on incompatible schema, source or dependency versions.

Before upgrading a real owner, stop ingress and its gateway and make the existing complete owner-volume backup. Keep `provider-secrets/`, the non-secret metadata DB, `provider-host.json`, and relay state together in a protected backup. The disposable restore rehearsal checks private-journal byte equality, `0600` permissions, relay-state inventory and startup quarantine alongside native history/artifact preservation. The backup is confidential: it intentionally contains renewable credentials. Do not export those files as public evidence. On a new host lifecycle, deliberately assign a new host ID rather than cloning a second live installation with the same host identity.

Rollback uses the previous Git version and a separate verified complete backup. Preserve post-upgrade data/receipts in their own backup; do not downgrade the live database or drop schema-14 tables in place. Restores remain quarantined until explicitly released. Initial checks used disposable owners/databases. On 26 October, the existing local owner was upgraded from schema 13 to 14 after a complete protected backup and quarantined restore rehearsal. All original agent/thread/message/goal IDs, original message/configuration bytes and migrations 1–13 checksums were verified unchanged. Confidential snapshots and credential journals stay outside public evidence.
