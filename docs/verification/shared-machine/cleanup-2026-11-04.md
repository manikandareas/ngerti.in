# Task desktop cleanup — 2026-11-04

Implemented following the user's explicit approval. Contract 1.30.0 adds `ngertiin.machine_window`, durable `machine_window` records, and owner query `GET /v1/machine/windows`.

## Behavior

- Cua `WindowsService.LaunchApp` opens task-owned browser/GUI-terminal windows. The browser uses the same retained Chromium profile. Ownership follows the root peer task across handoffs.
- The pinned Driver has no structured close-tab operation. Each task uses a temporary browser window; closing it also closes its tabs. Existing windows are never adopted. Untracked GUI windows/popups and tabs opened in unrelated windows remain intact. Agent instructions route temporary GUI work through the tracked tool.
- Cleanup waits for successful settlement of all runs in the task, completion of the whole peer chain, exited attributed processes, and resolution of uncertain/dispatched task effects. The shared input gate coordinates cleanup with agents and human takeover. Cleanup invalidates prior desktop observations; uncertain closure also fences input until reconciliation. There is no additional model/agent loop.
- `keep_open: true` or `retain` preserves a preview/result. Listing/retention are scoped to the server-owned thread and root task. The tool uses fixed executables/argv and validated HTTP(S) URLs, without arbitrary shell/CDP/app-launch parameters.
- Human takeover preserves currently managed windows because human edits/new tabs cannot be attributed safely. This is conservative retention after handback, not just a delay. Existing human windows are always untouched.
- Cleanup validates the upstream opaque window ID/epoch and PID, and uses `force: false`. Save prompts become `blocked`; lost acknowledgements become `unknown`. Neither is force-closed or blindly retried. Incomplete open/close records become unknown on recovery. Pending successful cleanup resumes after a backend restart when input is available.
- Working files, downloads, saved artifacts, profile/login data and the machine remain retained. Failed/cancelled/unknown tasks keep desktop context for diagnosis. Historical windows are not retroactively cleaned.
