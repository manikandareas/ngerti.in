## Objective

Deliver a Team agent's published skills and authorized tools while keeping app-account ownership, personal overlays and provider subscription choice separate.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Replace the single Composio owner identity with explicit organization integration and member-owned identities. Pin/test the supported session API and connected-account selection.
2. Implement organization/personal app connections, allowed agent/workgroup/tool/resource grants, reconnect and revocation. Keep pending OAuth and account routing bound to the initiating principal.
3. Extend scoped MCP gateway enforcement for supported server connections and native adapters. Inventory every supported catalog path; prevent raw/global native server credentials from bypassing application policy.
4. Publish immutable versioned application-owned skills on Team agents, with private user packages/overlays and management-authorized promotion. Keep inherited harness packages read-only and binding-scoped.
5. Preserve external-effect reservation, actor attribution, account serialization and unknown-outcome reconciliation across organization/member revocation.

## Acceptance criteria

- [ ] Authorized members use an organization app connection without authenticating their own account; a personal-mode integration requires that member's authorization.
- [ ] Choosing a different AI subscription does not change MCP account routing or expose that account's private harness skills.
- [ ] Search, schemas, execution and reconnect all enforce current ownership/grants; a revoked or mismatched connected account cannot be selected as fallback.
- [ ] Members receive the same enabled pinned Team skill revision; their chat edits cannot overwrite the shared package or reveal another user's private packages.
- [ ] Neither skill instructions nor an installed MCP entry grant additional resource permissions; stale native/catalog sessions cannot bypass disabled tools.
- [ ] Real Composio/MCP execution and native skill reads are recorded separately from catalog discovery, fixtures and OAuth completion; unknown effects are retained honestly.

## Verification and evidence
