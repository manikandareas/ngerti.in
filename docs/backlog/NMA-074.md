## Objective

Let authorized accounts create/join multiple organizations with organization-local Owner/Admin/Member roles and multiple Workgroup memberships.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. NMA-074 is Done for the verified backend organization-administration and execution-principal scope below. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Map Better Auth Organization to the product Organization and Teams to Workgroups. Define organization creation permission/limits separately from membership role.
2. Implement current-membership access context, role capabilities, protected Owner/Admin elevation and last-Owner invariants. Restrict organization deletion during the initial delivery.
3. Implement Workgroup creation/edit/membership, explicit All members audience and email-bound invitations with current role/group validation at acceptance.
4. Record an idempotent durable membership-provisioning intent for the user/organization; NMA-075 materializes its scoped private default-agent/DM. Preserve useful state through duplicate acceptance, missing provider setup and interrupted onboarding.
5. Implement offboarding generations and administrative audit records. Define retention, organization-agent ownership, suspended private responsibilities and explicit reassignment boundaries.

## Acceptance criteria

- [x] The same account owns one organization and is a Member in another without privilege inheritance; unauthorized organization IDs are rejected.
- [x] Creation policy can grant multiple-organization creation without granting access to another organization's private data or connection accounts.
- [x] Owner/Admin/Member capabilities and last-Owner protections match the main plan, including restricted Admin elevation.
- [x] One member can belong to multiple Workgroups; membership changes and deleted groups remove effective access rather than leaving stale grants.
- [x] Expired/cancelled/wrong-identity invites fail; concurrent acceptance produces one membership and one workspace-provisioning intent for later idempotent materialization.
- [x] Removal retains attributable team data, fences the former membership and pauses private scheduled work; deletion/export/retention behavior is explicit and tested.
