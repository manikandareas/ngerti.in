## Objective

Publish and verify the complete changed backend contract before web/Tauri consume the new multi-user behavior.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. This record is an implementation backlog, not completed implementation evidence. Targets are the server, web-client and Tauri; desktop-rs is paused.

## Implementation units

1. Inventory every API/entity/command/tool/event/viewer and its identity, organization, ownership, visibility, idempotency and error behavior.
2. Choose a justified breaking contract/version transition, regenerate executable export and examples, and document migration from the owner-only consumer contract without changing historical snapshots.
3. Produce an enumerated multi-organization and same-organization cross-user access matrix including receipts, derived files, background responsibilities and connection recovery.
4. Reverify PostgreSQL ordering/recovery, auth/revocation, native Cua isolation and both required harness adapters with distinct fixture/native/billing evidence.
5. Specify consumer onboarding, organization switch, selected connection, errors, stream renewal and disconnect semantics using authoritative responses.

## Acceptance criteria

- [ ] NMA-072–078 are complete for their stated scope and the changed export describes all registered surfaces, with explicit public/operator/user/run-lease/ticket authentication classes.
- [ ] Every affected surface has positive/negative access results and exact denominator, including private data between two members using one Team agent.
- [ ] Commit-ordered cursors, reconnect, lost acknowledgement, membership/grant changes and unknown external effects preserve scope and one durable operation.
- [ ] Codex subscription and Muse supported API-key inference/useful product tools are distinct from login/catalog tests; unverified capabilities remain explicit.
- [ ] No owner-wide event or generic entity endpoint, privileged database role, MCP route or viewer bypass remains outside the inventory.
- [ ] Consumer guides, schemas, provenance, limitations and local backlog agree; the historical NMA-060 acceptance is not relabeled as proof of this delta.

## Verification and evidence

HTTP/headless/native contract gate with disposable database/actors plus retained exact-version provider/machine observations.

At implementation time, retain a report under `docs/verification/nma-079/` with exact source/config/dependency versions, setup, denominator, pass/fail/skip, unknown outcomes and limitations. Preserve fixture, database, native/provider, browser/Tauri and distribution evidence as distinct proof. No such verification is claimed by this planning record.
