# Native browser, desktop, credential vault and human assistance

Task: [NMA-032](https://app.notion.com/p/404abdd618738139b305de65cc0bb257). Primary specification: [Ngertiin Multi Agent](https://app.notion.com/p/402abdd6187381e3a720f4b01d824e1a), its context/engine/acceptance documents, and the [capability adoption plan](https://app.notion.com/p/404abdd6187381d48e0cf27220703a95). All four dependencies were read live and are Done: NMA-028, NMA-029, NMA-030 and NMA-031. Knowledge-graph tools were unavailable; source inspection was used.

Status: **In Progress**. Local implementation and functional verification are delivered; the matched browser reliability gate remains unsatisfied. This report distinguishes retained failed candidates from final acceptance. It does not authorize or claim production rollout.

## Implemented behavior

The configured product browser uses native Hermes `browser_exec`, `browser_cdp`, `browser_dialog` and `browser_vault`. Actual desktop work uses native `computer_use`, backed by pinned Cua Driver inside an isolated Linux X11 capsule. Hermes remains the only model, admission, session, scheduling, stop and recovery authority. The capsule supervisor manages resources and receipts only.

`NMA_NATIVE_TOOLS_IMAGE` configures a reviewed immutable image. Without a valid installed image, the capability reports its missing prerequisite. E2B credentials cannot activate a browser fallback. The retired custom `computer` grant is unavailable; its tables, receipt identities, migrations and external-resource evidence remain retained.

The conversation Screen and login assistance dialog supplies authenticated viewing, private text entry, input takeover, explicit return, disconnect and pause. Both DM and group requests identify an authorized agent and thread; the caller never selects a container, display or CDP endpoint. Native screenshots become ordinary scoped binary file artifacts.

## Integration details

All native tools retain upstream names and schemas. `request_human` is a small product extension. A signed, live-authorized computer action maps to a single native approval scope; expiring that approval does not call native `clear_session`, which would also destroy the driver, capture target and persistent code kernel. Native standard-mode protections remain active.

The native CDP supervisor originally attached its first top-level page and child frames. Browser-harness can create further background page targets. A narrowly versioned adaptation attaches those new top-level targets and reuses upstream page-domain, frame and dialog-bridge handlers. It does not implement another browser planner. Exact touched upstream files are hash-bound in `runtime-pin.json`; upstream source patches remain empty.

Takeover first persists a pending fence, then drains the current scoped batch. A second agent batch cannot overtake the waiting human. Native browser helpers visibly focus the acting browser namespace for assistance. Explicit return rebinds that namespace to the human's visible tab and obtains a fresh frame before releasing ownership. The native worker remains the signal-owning process; it starts its isolated session bus and closes Chromium gracefully so persistent profile state can flush.

Native browser Python, terminal and desktop share the authorized capsule and private workspace. Each capsule has its own internal network and a separate volume-free public HTTP(S) relay. The relay resolves and pins public addresses and refuses private/loopback/link-local/metadata destinations. The model worker has no default external route, host mounts, Docker socket, provider credentials or control signing key. Fixture loopback access is explicitly enabled only in disposable test capsules.

The vault key and encrypted payload remain in the owner gateway's native vault, outside model-written Python and terminal code. Native origin checking, login-control classification and TOTP remain upstream. Classified page inspection/fills cross signed stdin RPC to the same browser supervisor. The model receives handles, metadata and status. Passwords, OTP seeds and private input never enter command-body tables or process arguments. Vault mutation receipts store an intent digest and metadata; an interrupted pending mutation is not blindly repeated. Configured native password-manager backends retain their upstream behavior; absent/locked managers and native keychains are explicitly unavailable on the tested capsule.

## API and persistence

The authenticated `nma.v1` commands are additive:

- `screen.action`: `thread_id`, `agent_id`, `action`; connect returns a five-minute `grant`. Frame, takeover, input, diagnostics, resume, revoke and pause require that grant.
- `browser.vault`: `thread_id`, `agent_id`, `action`, `item`; list/add/delete operate on native login metadata and encrypted payloads. Login input supports an optional authenticator seed. Secret request bodies bypass `nma_commands` and run history.
- `request_human(reason=...)`: persists assistance/input suspension and asks the owner to open the web screen. It does not request a password in chat or add goal activation approval.

Product schema remains 16. `screen_control` and `screen_grants` are additive supervisor-side tables; token plaintext is not stored. Grants bind the exact scope generation and require current product authorization at every projection. Revocation and expiry remove human access without automatically granting agent input. The tab's scoped grant survives reload in session storage; secrets do not. Viewing and input ownership remain distinct from authorization for an external transaction.

Explicit screen pause persists an input fence before draining and stopping the capsule; reconnect requires explicit return. A failed display in a running capsule is diagnosed within the API deadline and reports capability unavailability.

Native effect identity is persisted before dispatch. Successful returned work, rejected dispatch, failed observation and unknown partial actions remain distinct. Timeout, driver loss and cancellation never replay arbitrary code/input batches. The original unknown receipts survive disposable resource cleanup. Viewer frames are transient projections and are not cached in durable operation results. Native tool screenshots use the normal scoped file/event paths; known vault secrets are refused in generated file exports.

## Preservation and operator boundary

Existing accounts, custom profiles, transcripts, goals, skills, files, artifact IDs, effect/resource rows and historical migrations are not deleted or rewritten. Original E2B resources are not silently imported or deleted. Browser-only historical `computer` receipts remain historical browser receipts, and are never relabeled as desktop actions.

A newly selected native image creates its declared scoped resource mapping. An operator upgrading existing native controllers must stop/drain work, inventory controller/volume mappings and unknown effects, take verified private backups and explicitly reconcile the mapping. No automatic plaintext credential migration is performed. If no verified compatible profile mapping is supplied, the native browser is a fresh session; old resources and receipts remain retained for explicit reconciliation. NMA-039 owns wider account migration and NMA-027 owns deployment/operator release gates.

Files, downloads and the declared Chromium profile live on the private volume. Python variables, processes, driver handles, display RAM and tab execution state are process-lifetime state. Filesystem recovery does not claim restoration of live tabs or arbitrary in-memory execution. Pause preserves persistent files and receipts and records lost background process state. Explicit supervisor cleanup removes only its labeled disposable resources; it retains the receipt database and cannot confirm an unknown external effect.

## Final acceptance decision

The pre-registered quiet confirmation executed every cell: **7/9 successful**. Direct Hermes passed **3/3**, adapter **2/3**, authenticated HTTP **2/3**. First-progress p95 was **7.480s**, **9.540s**, **6.859s**; settlement p95 was **40.482s**, **52.165s**, **45.510s** (n=3 each). All latency gates passed in this cohort, but the product task-success rate did not reach 95%. The two failures each retained exactly one form POST and an unresolved native receipt: one model referenced an undefined Python `page`; one queried a form after navigation had removed it. Neither failed code batch was replayed. There were no observed duplicate form submissions or provider HTTP failures in these nine cells. Model/API misuse is an observed failure mode; it is not evidence that every integration fault has been ruled out.

The earlier v3 comparison remains **9/9 tasks with two first-progress latency misses**. Earlier 2/3 batches, the failed useful-task candidate and all repair/fault attempts remain separate. No selected run replaces or pools away a failed denominator. This work therefore **does not close NMA-032**. The remaining unit-1 acceptance is a matched direct/adapter/HTTP browser cohort satisfying the unchanged reliability and latency gates. Further native-tool usage/recovery work must preserve the current unknown-effect fence; changing unknown receipts into successes or replaying submitted forms is not an acceptable fix.

Closed native browser target: **1 passed**, 10.50s; native helpers recovered or retained the original unknown receipt without wrong-target input. The final gateway/recovery checks above also verify that explicit pause keeps input suspended and a dead display reports `CAPABILITY_UNAVAILABLE` before the protocol deadline.

Offline preservation rehearsal passed for **401 partition files**, product schema **16**, all domain rows/SQLite table counts, and **13 native volumes** with exact file hashes. Restore stayed quarantined and was never activated. Encrypted vault/key files, screen grants/control tables, native receipts, generated files, browser profiles and unresolved effects were retained in a private backup. Existing original accounts/resources were not migrated, deleted or reconfigured. Public evidence contains hashes/counts rather than credential-bearing archives.
