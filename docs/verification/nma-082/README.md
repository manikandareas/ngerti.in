## Failures, corrections and remaining boundaries

- The first private daemon adopted the existing host containerd and could not start its own image executable. A dedicated child containerd/socket/namespaces corrected ownership. The host daemon/containerd and unrelated applications were retained.
- Child containerd initially sent premature systemd readiness; its notification environment was removed. Established transit replies initially met the private-range denial; an established-reply rule now precedes that denial and remains scoped to the new transit.
- The first synthetic isolation setup failed inside a rolled-back transaction because one SQL parameter was inferred as both text and UUID. Separate parameters corrected the fixture; no synthetic user was committed by that attempt. The initial capacity fixture set the absolute creation quota to one instead of two and received 403 before a corrected declared third-domain test.
- The first new client cutover lacked service-readable parent/dependency directories, causing eight preflight restart attempts before any candidate application started. The service was stopped, secret-free release permissions corrected and ingress recreated. New staging now verifies source traversal and preflight as the actual service account before cutover.
- Native testing exposed DM history mixing despite correctly scoped backend snapshots. History is now filtered/merged by selected thread, the account snapshot projection is memoized, and late pagination is fenced. The actual Claire-to-Muse native switch was reproduced before the fix and observed clean afterward.
- The initial retained-receipt probe incorrectly expected an admission receipt to contain the later terminal revision. Receipts correctly preserve the original queued response; the corrected probe compares the unchanged current terminal run after replay. No new inference was admitted by that check.
- A post-restart Owner viewer exposed a real Cua startup race: the image waits for `/run/cua-desktop/desktop.env`, but Docker retained that old file and bus state while the next X session was starting. The daemon could start without its desktop provider. A bounded tmpfs at `/run` removes that stale state on every start; exact mount attestation and native `desktop_stream` readiness fail closed. Both domains were explicitly recreated with their home volumes retained, and both then passed a stop/start marker-clear, desktop capability and working-byte check. The final cold backup/start and native GUI desktop rendering passed again.
- A transport probe was initially run across the maintenance stop window and failed viewer issuance. The separately retained stable post-maintenance cohort passes all 13 checks. An early off-host verification also rejected an incomplete transfer; the final check requires the completed sidecar digest before authenticated inventory verification.
- An actual stop after public media hit systemd's 90-second timeout. A focused real authenticated-media regression reproduced a closed client, zero pending HTTP requests and a stale WebSocket count of one on Bun 1.3.10. The version-specific account HTTP adapter force-closes connections, drains actual requests within five seconds, preserves stop hooks and unreferences the stopped listener. Focused regression and awaited stop hooks pass; the deployed post-WSS stop measured 177 ms with exit status zero. The final profile stopped cleanly in 209 ms, and the service resumed with zero restarts. The first broad candidate cohort reached the old five-second fixture timeout in the existing revoke/replacement test; its two logins, three-second close bound and 1.5-second healthy-stream hold now have an explicit ten-second test budget. The unchanged assertions pass in the final 30-test cohort. No production auth retry or exact-schema bypass was added.

The historical intermittent authentication-introspection mismatch remains unconfirmed; the actual target's 80 initialization probes and final affected cohort pass. No authentication-specific retry or exact-schema bypass was added; startup failures remain observable. Web builds retain the existing large-chunk warning. Full documentation checking retains eight broken links in unchanged imported GPUI guides; the bounded checker byte-verifies those exact exclusions separately.

VPN/Tailscale enrollment, automatic PITR/off-host scheduling, arbitrary host enrollment, managed hosting/billing, general installers/notarization, other client platforms and further desktop-rs work remain outside this milestone.
