## Tujuan

Memory terjaga sesuai scope dan agent memakai skill harness plus skill aplikasi, dengan penulisan learning hanya pada level aplikasi.

## Dasar keputusan

[🧭 10 · Matriks keputusan fitur · Harness-first](../product/feature-decisions.md) — G01, G02, G03, G04, T03.

## Unit implementasi

1. Memory identities/revisions/delete dan scoped recall; produk-tools untuk melihat/mengoreksi/menghapus.
2. Skill inventory menampilkan asal harness vs aplikasi; assignment per agent dan conflict policy eksplisit.
3. App skill create/update/version/assets, trusted structured bridge/MCP dan crash-safe receipts.

## Acceptance criteria

- [x] DM-private/group/shared memory terpisah; foreign thread/context tidak ikut melalui recall atau skill assets.
- [x] Koreksi/hapus memakai identitas/revision yang tepat; tombstone/retry tidak memunculkan kembali fakta lama.
- [x] Agent mewarisi skill yang tersedia dari harness dan skill yang diassign app; source dan capability tetap dapat ditelusuri.
- [x] Agent hanya membuat/memperbaiki paket skill aplikasi; paket bawaan harness byte-stable dan tidak ditimpa.
- [x] Skill/assets/assignment bertahan restart, collision nama tidak silent overwrite, dan immutable results bisa ditinjau.
- [x] Round trip produk-tools terbukti dari setiap keluarga adapter yang diwajibkan, tanpa menjalankan loop model tambahan untuk sekadar tool dispatch.
