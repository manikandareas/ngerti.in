## Objective

Verify integrated desktop-rs visual, interaction, API and native-host parity against the frozen reference, then produce a tested local development bundle. Earlier milestones already verify their own slices; this milestone owns cross-feature journeys, regressions and the final difference register.

## Implementation units

1. Execute the complete versioned surface/state manifest with matched Tauri/GPUI source, data, themes, dimensions, scale, fonts, locale/time zone and deterministic animation timestamps. Review screenshot differences alongside behavior assertions.
2. Run real-API native DM/group/creation, queue/steer/stop/question/approval, Goals/Routine, Settings/provider, memory/skills, files/Focus/tree and Computer journeys. Include supported Codex/ChatGPT and explicitly selected Muse API-key paths; keep inference/tool/billing stages distinct.
3. Verify fresh app-profile startup, full relaunch, pending draft/upload/operation recovery, dropped acknowledgement, event reconnect, external/owned backend exit and simultaneous client scope isolation using disposable data. Include IME, keyboard/focus, accessibility, long content and minimum desktop-window behavior.
4. Measure matching performance workloads and resolve regressions against the NMA-066 budgets. Keep a per-surface difference register with severity, exact reproduction, source and outcome. Close material gaps rather than masking captures or silently replacing functionality.
5. Package a macOS ARM64 development app with the selected Rust/native resources and backend runtime/dependency closure. Verify the actual bundled executable outside the repository working directory with isolated state; document setup and lifecycle.
6. Publish local run/build/diagnostic/rollback and source-adoption notes. Keep the Tauri reference and fixture experiment until a later explicit active-host decision. Record remaining platform and distribution gates separately.

## Acceptance criteria

- [ ] Every required baseline surface/state maps to implementation and retained native evidence, with planned/executed/pass/fail/skip denominators. No unexplained material visual/interaction gaps remain; any scoped deviation has a specific user decision and cannot be hidden inside a percentage score.
- [ ] Full native journeys prove message/attachment linkage, scope, selection/copy/IME/focus and recovery using authoritative API state/receipts. Screenshots, fixture tests and build success are reported separately from real provider/tool execution.
- [ ] Both required harness paths are exercised for the native consumer's affected behavior. Login, catalog, inference, useful product tools and effective billing remain separate observations; no silent subscription-to-key fallback is introduced.
- [ ] Restarts and uncertain acknowledgements preserve data and one operation identity; the app never replays unknown external work blindly. No unrelated profile, credential, conversation, responsibility or shared-machine data is reset during tests.
- [ ] Matched performance results include visible and hidden workloads, frame/latency/CPU/memory measures and actual machine/display conditions. Agreed regression budgets pass; GPUI does not receive an assumed smoothness/resource advantage.
- [ ] The actual local macOS ARM64 development bundle starts, loads original assets, attaches/starts only the correct backend, reconnects and shuts down correctly from isolated state. No repository credentials, private state or short-lived viewer ticket is bundled.
- [ ] The platform matrix clearly identifies executed macOS checks and unverified Windows/Linux/physical-device conditions. Signing, installers, update delivery and fresh-device distribution are not certified by this bundle.
- [ ] NMA-066–070 evidence and affected specifications/index/status agree. NMA-063 product-wide acceptance and NMA-064 installation retain their own status/requirements; this native gate does not mark them Done or remove Tauri automatically.
- [ ] Bundle/source/runtime inspection confirms no shipped web-client distribution or React/Lexical/PDF.js application UI and no TypeScript-generated runtime avatar. WebViews are limited to the documented HTML/Computer surfaces; matching screenshots alone cannot satisfy this architecture criterion.
