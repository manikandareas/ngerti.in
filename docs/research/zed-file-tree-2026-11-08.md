## Interaction behavior to retain

Right expands a closed selected directory; on an already expanded directory it advances to the next visible entry. Left collapses the selected expanded directory, otherwise finds an ancestor to collapse/select. Selection is scrolled minimally into view. A folder click toggles it; file clicks open preview tabs, while double-click changes focus/permanence behavior. These are existing editor semantics, not a mandate to add editor tabs to Ngertiin. Sources: [expand/collapse, lines 1482–1588](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project_panel/src/project_panel.rs#L1482), [selection visibility, lines 1404–1440](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project_panel/src/project_panel.rs#L1404), [click handling, lines 6496–6609](https://github.com/zed-industries/zed/blob/b5cd310b3b54dfc659fcc06453e6358843dfe216/crates/project_panel/src/project_panel.rs#L6496).

## Ngertiin adaptation

Use a compact flat hierarchy with consistent row height, a regular 14-point filename, 16-point format icons, a true icon disclosure slot and fixed per-depth indentation. Keep the existing Material Icon Theme associations and Ngertiin semantic colors; use the both-mode alignment rule if chevrons and folder icons are both shown. Give the selected row a quiet fill plus a separate focus outline, preserving Ngertiin's existing single-selection contract. Subtle ancestor guides should sit behind content and strengthen for the selected branch.

Keep Back/Working files/Close in the existing contextual panel, existing lazy server reads, per-folder pagination/retry/refresh, cancellation fencing, shared-machine scope and Focus return state. A narrow-panel filename ellipsis plus full-path tooltip is a deliberate Ngertiin adaptation if horizontal scrolling is omitted. Errors/loading/more are folder-owned rows at the folder's child indentation; they must not interrupt unrelated branch geometry.

Do not port Zed's project/worktree domain or add its crate dependency. Git status, diagnostics, file mutations, drag/drop, compact directory folding, multi-selection and sticky ancestors are not required by the requested visual adoption. If virtualizing the native tree, include folder loading/error/more rows in the same flattened model and keep stable path-derived row identities and the same retained scroll handle.

Upgrade checks: compare the pinned modules above; verify both themes, root/deep sibling alignment, long names, selection/focus/hover distinction, lazy folder errors and pagination, keyboard visibility, and Focus Back restoration. This research did not run a Zed native screenshot comparison or establish Ngertiin completion.
