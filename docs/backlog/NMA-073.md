## Objective

Replace installation-wide user access with authenticated accounts and revocable device sessions, while defining web and Tauri authentication over HTTPS.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. NMA-073 is Done for the verified backend authentication/session and headless native-client scope described below. Targets are the server, web-client and Tauri; desktop-rs source was retired on November 15.

## Implementation units

1. Prove and pin Better Auth, its PostgreSQL integration, Elysia integration and OAuth Provider compatibility on the selected Bun version. Record provenance and a minimal representative flow before expanding configuration.
2. Implement account registration/login, verification and recovery with a selected email delivery adapter. Guard the first-owner bootstrap with an operator-controlled, expiring one-use mechanism.
3. Implement secure web sessions/cookies and CSRF/origin validation; define the public-client PKCE flow and API access-token verification for Tauri without an embedded client secret.
4. Separate user sessions, operator credentials, run leases and viewer tickets. Map token subjects to application users and validate issuer/audience/current session state.
5. Implement per-device list/revoke/logout/renewal and stream teardown. Document session-token versus OAuth-token paths; choose one native baseline rather than mixing plugins.

## Acceptance criteria

- [x] An uninvited or unauthorized signup cannot become the initial Owner or gain operator access; bootstrap replay and expiry are rejected.
- [x] Web login, verification, recovery, logout and session revocation work through real HTTP with the configured email adapter or controlled delivery capture.
- [x] A public native client completes authorization code plus S256 PKCE and renewal; invalid state/verifier, redirect, issuer/audience and revoked tokens fail safely.
- [x] One device can be revoked without logging out other authorized devices; expired or revoked sessions cannot open API, SSE or viewer sessions.
- [x] Passwords, auth headers, codes and tokens are absent from application events, logs, receipts, frontend storage and public error bodies.
- [x] Exact dependency pins, database schema, email configuration and HTTP/native-client contract are documented; auth compatibility proof is distinct from completed product onboarding.
