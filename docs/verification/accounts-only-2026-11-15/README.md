# Account-only authentication and unified development — 2026-11-15

Owner instruction: remove the auth-mode gate and legacy authentication code; support development without Resend credentials; make `bun dev` start server, web and Tauri together. Account authentication and organization authorization remain mandatory.

Implementation includes mandatory authentication services, cookie/native OAuth sessions, a private persistent development secret and local inbox, automatic first verified local Owner, the UI-only Tauri account client with version-2 profiles, and an owning development launcher. The installation-bearer proxy, local desktop supervisor and bundled Bun/backend are removed. Retained data and unrelated PostgreSQL work are preserved; unbound historical records remain quarantined without blocking new organizations.

Development uses API `127.0.0.1:8000`, browser/auth origin `http://127.0.0.1:3001`, inbox `http://127.0.0.1:8025` and a separate desktop profile at `.dev/development-client`. PostgreSQL remains required. `NGERTIIN_AUTH_SECRET` can be omitted in development; the generated secret persists under the private state directory. Email delivery defaults to local files even when a Resend key exists. Production retains explicit HTTPS, secret and Resend configuration. Role, membership, private-data and billing checks remain enforced.

Tauri has a separate macOS development application identity, uses the shared Vite server, completes system-browser S256 PKCE, and retains renewal credentials in Keychain. It receives a restricted development environment rather than backend/provider secrets. Quitting the client leaves the API and web running; Ctrl+C stops only processes owned by the launcher. Existing version-1 profiles and installation identity files are preserved, but their legacy authentication fields are not consumed.
