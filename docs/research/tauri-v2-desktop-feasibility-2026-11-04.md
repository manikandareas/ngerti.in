# Tauri v2 desktop feasibility: primary-source evidence

Date: 2026-11-04. Status: design research; no Tauri application was built, installed, profiled, or accepted in this investigation. This note supports the [desktop architecture proposal](../architecture/tauri-desktop-design-2026-11-04.md); recommendations below require implementation authorization and native verification.

## Recommended boundary

Use one Tauri Rust host, one main WebView, and the existing Bun backend. Move Electron's small host responsibilities—window/tray/menu lifecycle, process supervision, loopback gateway, external links and Computer visibility bridge—to Rust. Keep the React frontend and Ngertiin backend as the product implementation. Do not create a second domain lifecycle in Rust or introduce a second Bun process merely to retain Electron's gateway.

Tauri itself remains a multiprocess application: the privileged core orchestrates native features while WebViews render the frontend. On macOS its engine is WKWebView/WebKit; Windows uses WebView2 and Linux uses WebKitGTK. Replacing the shell therefore changes browser behavior as well as the host runtime. These documented facts suggest potential shell savings, but establish no numerical memory reduction, faster React rendering, or animation guarantee. Measure host, WebView content/GPU/network processes, Bun, harnesses and Docker separately. [Process model](https://v2.tauri.app/concept/process-model/), [WebView engines](https://v2.tauri.app/reference/webview-versions/).

The public registries queried on this date reported stable Rust `tauri` **2.12.5**, npm `@tauri-apps/cli` **2.12.4**, and npm `@tauri-apps/api` **2.12.4**; the Rust registry's highest version was a 3.0 alpha, which is outside this v2 proposal. These are researched candidates, not tested versions or a requirement that every crate share a version number. Pin the compatible dependency set and retain Cargo/Bun lockfiles when implementation starts. [Official releases](https://github.com/tauri-apps/tauri/releases), [Rust registry](https://crates.io/api/v1/crates/tauri), [CLI registry](https://registry.npmjs.org/@tauri-apps/cli/latest), [API registry](https://registry.npmjs.org/@tauri-apps/api/latest).

## Transport and origins

The lowest-change candidate retains the current stable `http://127.0.0.1:<saved-ui-port>` origin. A Rust gateway serves the packaged frontend and proxies HTTP/SSE to the private backend port, injecting the installation token host-side. The Computer media route must preserve the current generated-protocol URL rewriting, WebSocket upgrade/streaming, expiry and control revision behavior. This is a design recommendation based on [the existing Electron host](../../apps/desktop/src/main.ts), [gateway](../../apps/desktop/src/gateway.ts) and [machine evidence](../verification/shared-machine/README.md), not an already-proven Rust implementation.

Tauri normally serves frontend assets with its custom protocol. Its localhost plugin explicitly warns that HTTP asset serving adds security risks. Keeping Ngertiin's controlled gateway is consequently an intentional tradeoff: bind only loopback, verify Host/Origin and route ownership, reject occupied/unowned listeners, preserve token separation and stream responses without whole-body buffering. Do not use the localhost plugin in addition to a second gateway. If the WebView is loaded from HTTP, native command access needs a deliberately scoped remote capability; bundled-code access does not automatically transfer to arbitrary remote pages. [Localhost plugin](https://v2.tauri.app/plugin/localhost/), [remote capability rules](https://v2.tauri.app/security/capabilities/#remote-api-access).

A custom-protocol frontend remains an alternative for a later transport spike. It changes origin, cookie/storage and network assumptions; backend CORS must allow the actual origin with credentials where required. Credentialed CORS cannot use wildcard origins. Native `EventSource` exposes its URL and `withCredentials`, rather than arbitrary request headers; native WebSocket's constructor takes URL/subprotocols, rather than an Authorization header argument. Preserve host-side token handling instead of leaking the installation token into frontend URLs or adding one IPC hop per streamed delta. [CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS), [SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events), [WebSocket constructor](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/WebSocket).

Tauri's Windows/Android custom-protocol HTTP/HTTPS option also changes storage location when changed between releases; HTTPS mode cannot freely fetch HTTP endpoints. Treat origin and storage identity as a versioned choice. [Configuration: useHttpsScheme](https://v2.tauri.app/reference/config/#usehttpsscheme).

## Native lifecycle and packaged backend

Tauri can bundle external binaries via `bundle.externalBin`; sidecar filenames require the supported target triple suffix. Keep the existing Bun runtime + backend source/production dependencies/resources packaging initially. Compiling the backend into a single Bun executable is a separate experiment; it is not required for Tauri and does not prove native dependency/resource compatibility. Build ARM64 first, then prove Intel separately if it is in the agreed distribution scope. [Sidecar packaging](https://v2.tauri.app/develop/sidecar/), [current packaging closure](../../apps/desktop/scripts/package.ts).

Supervision must distinguish owned and attached backend processes, verify instance identity/readiness, bound stdout/stderr queues, enforce restart backoff, and stop only owned process trees. A shell swap does not implement these behaviors automatically. Close-to-tray should release human Computer control and suspend visual work while backend Goals/Routines continue. Explicit Quit must release control, drain/stop owned backend/harness resources according to current policy and leave the retained Linux machine intact. Use native close/exit events and tray actions; keep potentially blocking process/network work off the UI thread. [Window events](https://docs.rs/tauri/2.12.5/tauri/enum.WindowEvent.html), [application events](https://docs.rs/tauri/2.12.5/tauri/enum.RunEvent.html), [tray support](https://v2.tauri.app/learn/system-tray/).

WKWebView background behavior deserves explicit testing. Tauri documents timer throttling and possible unloading of a hidden/minimized view; control over this policy is available on macOS 14+. Product continuation therefore belongs in Bun. Persist drafts independently of WebView lifetime, stop UI frame work on hide, release viewer leases from the host, and reconnect/resnapshot on show or wake. Do not globally disable throttling to keep agent work alive. [Native WebView builder](https://docs.rs/tauri/2.12.5/tauri/webview/struct.WebviewWindowBuilder.html#method.background_throttling).

## Capability and IPC corrections to skill examples

The supplied skill is useful orientation but is not an authoritative configuration schema. Official documentation establishes these important corrections:

- App commands registered through `invoke_handler` are callable by all application windows/WebViews by default. Use `tauri_build::AppManifest::commands`, generated app permissions, explicit capabilities and command-level caller/input checks. Plugin permission defaults differ; do not summarize the whole system as deny-everything. Capabilities from multiple matches merge. [Capabilities](https://v2.tauri.app/security/capabilities/).
- `app.security.assetProtocol` with `enable` and `scope` controls local asset access; an `assetScope` key is not this v2 configuration. Keep arbitrary user files behind scoped backend/native workflows. [Asset protocol configuration](https://v2.tauri.app/security/asset-protocol/).
- Top-level command argument names use camelCase by default, but nested Rust DTO fields require explicit Serde naming such as `#[serde(rename_all = "camelCase")]`. Generate/check shared types and include a nested DTO contract test. [Command arguments](https://v2.tauri.app/develop/calling-rust/), [Serde field names](https://serde.rs/attr-rename.html).
- Tauri events suit small notifications; ordered Channels are the documented streaming mechanism. Use events for visibility/readiness, retain existing HTTP/SSE for domain state, and introduce Channels only for bounded native streaming needs. Unregister listeners when their consumer unmounts. [Events and Channels](https://v2.tauri.app/develop/calling-frontend/).

Keep the first native bridge to host visibility subscription and `report_computer_view(active, revision)`. Handle navigation, external opening, downloads, menus and logs directly in Rust instead of exposing generic shell/filesystem/opener commands to the renderer. Validate reports against the backend's current interactive ticket/revision and actual host visibility; a renderer report must not create or extend control authority. Keep release authority in the host/backend so iframe unload or JS failure cannot leave human control indefinitely owned.

The current Computer iframe is same-origin with the main HTTP UI. A capability for the main window/WebView is consequently **not proof of iframe isolation**. In pinned 2.12.5 source, internal `InvokeRequest.url` represents a caller URL and feeds ACL resolution, but is explicitly unstable; public `InvokeMessage` exposes command, WebView, payload and headers, while public `ipc::Request` exposes body and headers, without a stable authenticated frame-URL accessor. The custom-protocol transport obtains its URL from the HTTP Origin header, which cannot distinguish same-origin paths; the postMessage transport uses the native request URI. `Webview::url()` returns the current WebView URL, not proof that the top frame invoked a command. [Pinned WebView source](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.5/crates/tauri/src/webview/mod.rs), [public IPC source](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.5/crates/tauri/src/ipc/mod.rs), [IPC transport source](https://github.com/tauri-apps/tauri/blob/tauri-v2.12.5/crates/tauri/src/ipc/protocol.rs).

Do not base a privileged bridge on a caller-supplied URL/header or window label alone. Same-origin frames can also access the parent under normal browser rules. If future native privileges require stronger separation, place viewer/preview content on a dedicated origin or separate WebView with zero capabilities and prove denial with native tests; account for Tauri's documented Linux/Android iframe-origin limitation before claiming cross-platform isolation. For the initial narrow bridge, explicitly test frame attempts to report another revision, release stale control or acquire native privileges. [Remote API iframe limitation](https://v2.tauri.app/security/capabilities/#remote-api-access).

Use a CSP matching the actual deployment: scripts/styles/assets, same-origin API/SSE, explicit Computer frame/media destinations, and required IPC sources. Tauri can modify bundled assets for CSP, but the HTTP gateway must send an appropriate CSP itself. Do not copy sample remote fonts or permissive sources into Ngertiin's policy. [Tauri CSP](https://v2.tauri.app/security/csp/).

## Feature preservation and release boundaries

| Feature | Design and proof required |
| --- | --- |
| Computer | Test the actual Cua iframe + generated protocol + media WebSocket in WKWebView. Verify decode/display, pointer/keyboard input, IME, resize/DPI, read-only mode, takeover/handback, revision expiry, hidden release, renewal, reconnect and backend restart. The repo's old noVNC path was removed; testing VNC would test the wrong viewer. [Current viewer](../../apps/web-client/src/features/conversation/components/machine-viewer.tsx), [current evidence](../verification/shared-machine/README.md). |
| Native input | Prove text selection/copy, paste images/files, keyboard shortcuts, IME composition and HTML file input. Tauri's own drag/drop handler is enabled by default; Windows HTML5 drag/drop needs that handler disabled or an explicit native adaptation. Test OS-file drops separately from internal UI dragging. [Drag/drop setting](https://v2.tauri.app/reference/config/#dragdropenabled). |
| Attachments/downloads | Retain authenticated backend routes. Test file picker/upload, large-file streaming/cancel, filenames and downloaded-byte hashes. Native download/new-window/navigation hooks exist, but Electron handlers do not port automatically. [Native builder hooks](https://docs.rs/tauri/2.12.5/tauri/webview/struct.WebviewWindowBuilder.html), [dialogs](https://v2.tauri.app/plugin/dialog/). |
| Clipboard | Prefer standard edit behavior where it works. Add narrowly scoped native clipboard operations only for proven gaps; clipboard plugin operations require explicit permission. An iframe's `allow` attribute alone does not prove WKWebView OS permission or activation behavior. [Clipboard plugin](https://v2.tauri.app/plugin/clipboard/). |
| Provider/Composio login | Keep authorization in the system browser. Preserve the provider's supported loopback/device callback flow; use a deep link only if it is an agreed supported redirect. Validate transaction state, expiry and PKCE where applicable, and prove relaunch/cancel/retry. macOS deep links require registration in configuration. [Native OAuth best practice](https://www.rfc-editor.org/rfc/rfc8252), [opener](https://v2.tauri.app/plugin/opener/), [deep links](https://v2.tauri.app/plugin/deep-linking/). |
| Secrets | Retain the current backend-private credential ownership and billing method. Stronghold is a password-derived encrypted secret store, not automatically macOS Keychain or transparent migration. A future Keychain integration needs a separate design and test; it is not a shell-migration dependency. [Stronghold](https://v2.tauri.app/plugin/stronghold/). |
| Notifications | Native notification support is available, but permissions, click/reopen behavior and hidden-window delivery require testing in the packaged app if this feature is already in scope. Plugin availability adds no new product commitment. [Notifications](https://v2.tauri.app/plugin/notification/). |
| Distribution | Local development acceptance is separate from a distributable release. The updater requires artifact signatures and normally enforces TLS; do not enable its insecure transport override. Apple code signing/notarization is a separate trust mechanism from updater signatures, including bundled executable handling. [Updater](https://v2.tauri.app/plugin/updater/), [macOS signing](https://v2.tauri.app/distribute/sign/macos/). |

## Evidence gates

Use the exact same dataset, frontend/backend revision, release-mode assets, display size/refresh rate and workload for Electron/Tauri comparison. Record cold/warm launch, idle/streaming/Computer CPU and memory, main-thread stalls, frame intervals and input latency. Browser fixtures establish frontend logic; native packaged tests establish WKWebView behavior. No RAM/FPS prediction in a framework article substitutes for this comparison.

The current official testing guide supports macOS through `@wdio/tauri-service` and an embedded WebDriver plugin. Direct standalone `tauri-driver` remains Windows/Linux only; the paid CrabNebula route is another documented option. A blanket claim that native Tauri automation on macOS is impossible is now stale. Evaluate the embedded route in the spike, keep automation/control plugins out of production builds, and retain native visual/manual evidence for OS dialogs, clipboard/IME, Cua media and animation smoothness. Playwright WebKit browser results still do not establish packaged WKWebView acceptance. [Current Tauri testing guide](https://v2.tauri.app/develop/tests/webdriver/).

Decision remains conditional: adopt the Tauri shell after the native feature matrix and matched performance gates pass. If the Cua viewer, authentication, background continuation or native input cannot meet the gate, record the specific failure and keep the existing Electron build as the reproducible comparison baseline while resolving it.
