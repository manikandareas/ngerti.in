## Objective

Verify integrated desktop-rs visual, interaction, API and native-host parity against the frozen reference, then produce a tested local development bundle. Earlier milestones already verify their own slices; this milestone owns cross-feature journeys, regressions and the final difference register.

## Implementation units

1. Audit the complete assistant-studio component/state catalog against production native paths and execute representative native visual and interaction journeys under the [focused completion decision](../development/nma-071-closure-scope-2026-11-09.md). Retain exact source, data and capture conditions; keep the original exhaustive matrix unexecuted rather than relabeling it.
2. Run real-API native DM/group/creation, queue/steer/stop/question/approval, Goals/Routine, Settings/provider, memory/skills, files/Focus/tree and Computer journeys. Include supported Codex/ChatGPT; Muse API-key verification is a separate follow-up under the [2026-11-08 owner decision](../development/nma-071-scope-2026-11-08.md). Keep inference/tool/billing stages distinct.
3. Verify fresh app-profile startup, full relaunch, pending draft/upload/operation recovery, dropped acknowledgement, event reconnect, external/owned backend exit and simultaneous client scope isolation using disposable data. Include IME, keyboard/focus, accessibility, long content and minimum desktop-window behavior.
4. Check for material stalls, runaway redraws and unusable long-content behavior during the native journeys. Comparative Tauri/native performance and exhaustive paired workloads are not closure prerequisites under the owner decision. Keep a per-surface difference register with severity, exact reproduction, source and outcome. Close material gaps rather than masking captures or silently replacing functionality.
5. Package a macOS ARM64 development app with the selected Rust/native resources and backend runtime/dependency closure. Verify the actual bundled executable outside the repository working directory with isolated state; document setup and lifecycle.
6. Publish local run/build/diagnostic/rollback and source-adoption notes. Keep the Tauri reference and fixture experiment until a later explicit active-host decision. Record remaining platform and distribution gates separately.

## Acceptance criteria

- [x] All 67 assistant-studio states map to native implementation; representative native evidence, reused earlier proof and unexecuted exhaustive cases have distinct denominators. No unexplained material visual/interaction gaps remain; any scoped deviation has a specific user decision and cannot be hidden inside a percentage score.
- [x] Full native journeys prove message/attachment linkage, scope, selection/copy/IME/focus and recovery using authoritative API state/receipts. Screenshots, fixture tests and build success are reported separately from real provider/tool execution.
- [x] The Codex/ChatGPT path is exercised for the native consumer's affected behavior. Muse API-key verification is separately retained under the owner decision. Login, catalog, inference, useful product tools and effective billing remain separate observations; no silent subscription-to-key fallback is introduced.
- [x] Restarts and uncertain acknowledgements preserve data and one operation identity; the app never replays unknown external work blindly. No unrelated profile, credential, conversation, responsibility or shared-machine data is reset during tests.
- [x] Native journeys have no unresolved material responsiveness defect. Existing measurements retain their exact conditions; exhaustive paired workload and 1:1 performance matching are not required by the [owner decision](../development/nma-071-closure-scope-2026-11-09.md). Superior native performance is not asserted without measurement.
- [x] The actual local macOS ARM64 development bundle starts, loads original assets, attaches/starts only the correct backend, reconnects and shuts down correctly from isolated state. No repository credentials, private state or short-lived viewer ticket is bundled.
- [x] The platform matrix clearly identifies executed macOS checks and unverified Windows/Linux/physical-device conditions. Signing, installers, update delivery and fresh-device distribution are not certified by this bundle.
- [x] NMA-066–070 evidence and affected specifications/index/status agree. NMA-063 product-wide acceptance and NMA-064 installation retain their own status/requirements; this native gate does not mark them Done or remove Tauri automatically.
- [x] Bundle/source/runtime inspection confirms no shipped web-client distribution or React/Lexical/PDF.js application UI and no TypeScript-generated runtime avatar. WebViews are limited to the documented HTML/Computer surfaces; matching screenshots alone cannot satisfy this architecture criterion.
