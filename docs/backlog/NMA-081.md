## Objective

Run the shared web-client in Tauri as a remote client with native session security and no ownership of the central server lifecycle.

The [main server-organizations plan](../architecture/server-organizations-plan-2026-11-12.md) owns the design, scope defaults, diagrams and privacy model. The implemented macOS development scope and its proof are retained in the verification report below. Targets are the server, web-client and Tauri; desktop-rs source was retired on November 15.

## Implementation units

1. Add explicit local-development versus remote profile modes with trusted HTTPS server identity, validated routes and isolated local presentation state.
2. Implement system-browser PKCE login, bounded loopback callback/state checks, native access-token renewal and OS secure credential storage; keep renewal/provider tokens out of WebView JavaScript.
3. Adapt the narrow native gateway for authenticated API/SSE/upload/download/viewer traffic to the selected server while preserving Host/Origin/path/redirect controls.
4. Make close/reload/quit/logout revoke only this client's eligible tickets/sessions and leave the remote backend, harnesses and responsibilities running.
5. Exercise deep link or invitation handoff, expired/revoked tokens, reconnection and profile/server/account switching; retain local supervision only when explicitly configured.

## Acceptance criteria

- [x] A Tauri remote profile connects to the real server and completes login without a local backend, Codex/Muse executable or Cua machine requirement.
- [x] Native callback and renewal tokens remain private and origin-bound; invalid/late callbacks, redirects and leaked renderer headers cannot obtain credentials.
- [x] Closing or quitting one client leaves server work and another client's session alive; logout closes affected viewer/input and streams.
- [x] Relaunch/reconnect/retry preserves the correct server/user/organization, drafts and pending command identity without duplicate work.
- [x] The actual supported macOS development app completes the web onboarding/agent/connection/file/Computer workflows through its native gateway.
- [x] No desktop-rs implementation or installer acceptance is required or claimed.
